农场**（fault farm）批量生产带标签的 comm_log/1 日志——真值不靠人标注，靠**注入

再经规则检出与骨架判卷，形成全链闭环并注册为总门禁 G11。

**农场结构（每一环都有门）**：


- **农场内置桩（静默/RST/乱码）与真从站并存**：fixture 表达不了的从站侧故障
  用行为等价桩构造，端口段 15030+ 与协议域门禁 15020-15024 隔离。
- 检出引擎与 forensics.py 同纪律但不同对象（帧级 JSONL vs 设备文本日志），
  不共用代码与词表；两者都不是在线检测，是离线归因。

### 11.2 CSV 列语义与映射规则（knowledge/protocols/pcap_mapping.json）

| CSV/pcap 来源 | 契约字段 | 规则与依据 |
|---|---|---|
| CSV 第 0 列 packet_index | （对齐键 / seq） | 第 N 行↔第 N 包，实测逐一对齐；seq=全局包序号，任何流内严格递增（I1 自动满足）且可回查原始包 |
| CSV 第 1 列 label | 扩展字段 label | 0=正常 1=攻击窗口，按帧起始包号透传（判卷真值源） |
| pcap 包头 ts_sec/usec | timestamp_utc | epoch→UTC ISO8601 微秒精度 Z 结尾；抓包时刻即帧时刻 |
| TCP 端口 | direction | 源端口==502→resp，否则→req（从站监听 502）；TCP 面无 broadcast |
| MBAP 第 7 字节 | unit_id | 透传（数据集事实：恒为 1，6 从站靠 IP 区分，不猜改） |
| PDU 首字节 | function_code | fc&0x80→取低 7 位基础码，异常性转 exception_code（AP V1.1b3 §4.5） |
| 异常 PDU 第 2 字节 | exception_code | 仅 resp 可带（I3 同校验）；异常帧附 frame_hex（契约 recommended_when） |
| 从站端点 ip:502 | device.host_or_port | req=目的 IP、resp=源 IP——检出流键按设备聚合；主站端入扩展字段 client |

解析器：每条双向 TCP 流一个顺序携带缓冲，贪心吐完整 MBAP+PDU——粘包（一段多
PDU）与拆包（PDU 跨段）同一路径，无重组排序；MBAP 头非法/流尾残字节如实计数
（malformed_leftovers）不硬映射（核心六段实测全 0）。功能码口径：1-4=读、
5/6/15/16=写（判卷统计 write_frames 用）。

入库夹具（`knowledge/protocols/pcap_samples/`）：lemay_sample.pcap（polling_only
前 30 包**原字节**截取）+ lemay_sample.csv（前 30 行标注）+
lemay_sample_expected.json（期望映射 10 帧，首行与原始字节人工核对：pkt#4
payload `0594 0000 0006 01 03 0008 0004` = FC3 读保持寄存器→192.168.1.106:502）。
开发中真实抓过一个 PDU 切片 off-by-one（FC 读成 uid 恒 1）——被逐包 hex 人工核对
逮住，已修并以测试钉死（tests/test_lemay_corpus.py 首行断言）。

含义是「37 段风暴的证据行盖住了 49.77% 的窗口帧」，不是「检出了一半攻击」——
