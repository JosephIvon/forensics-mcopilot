## 1. 项目整体架构

### 1.1 它解决什么问题

把运动控制上位机软件工程的工业需求基线（20 条：11 工程职责域 + 9 工程能力要求）逐条量化后，项目给出的结论是：
**AI 能吃掉的是「工程化负担」，不是「工艺判断力」。** 判据有三条 —— ① 产出物是文件而不是手感；② 能被规则或数值验证；③ 错了能被机器发现。

按这条判据，**伺服在线自整定/惯量辨识**（需示波器 + 上机闭环）被明确划出自动化范围；**伺服离线波形诊断**（读波形 → 反推等效参数 → 候选根因）保留在 AI 侧。这一拆分是全仓库的语义地基。【库内】`knowledge/requirements_map.json`（20 条目）、`knowledge/coverage_ledger.json`（15 条 entries / 7 条 uncovered / 2 条 seams）。

### 1.5 六条贯穿全仓的不变量

1. **知识层是唯一事实来源。** 阈值、日志格式、评审规则、伺服判据、厂商绑定、能力矩阵全在 `knowledge/`，改配置不改代码。【库内】`README.md` §五末句。
2. **每条结论必须能回查。** 日志类结论带 `L<行号>` 证据；通信类检出带行号 + 流内 `seq`；文档类引用带 `文件:行号` 且由 `verify_doc_refs.py` 机检。
3. **「不可评估」是一等公民。** `not_evaluable` 与 `not_hit` 分开；`servo_rules.json` 有 15 条 `not_evaluable_asks` 明确「要什么数据才能评」。【实测】`servo_rules.json`。
4. **结论必须标证据等级。** `confidence_model` 14 条 + `caps` 4 条给置信度**封顶**（如 `bandwidth_estimate` ≤0.6、`no_static_segment` ≤0.55、`counterfactual_unresolved` ≤0.6、`derived_velocity_feedback` ≤0.7）；没有 basis 的条目不给百分比。
5. **独立基线不得自我验证。** 5 个 `verify_*.py` 只用标准库、**不 import mcopilot** 的业务函数 —— 拿被审的代码验被审的结论就是「同源自证」。
6. **失败必须响亮。** 门禁脚本统一 `-ErrorAction Stop` + `trap` 兜底 `exit 100`（异常路径 ≠ 0，「崩溃即过」被显式禁止）；缺解释器 → `exit 2`。【库内】各 `gate_*.ps1` 头部。

### 3.3 `servo.py` 详解（仓库最重的模块，3 999 行）

按功能面分 7 组：

| 组 | 函数 | 说明 |
|---|---|---|
| 数据归一化 | `load_waveform` `load_events` `load_axis` `load_drive_params` `verify_events_sync` | 中英列名皆认；`Waveform.error_signal()` 在 `err` 缺失时按 `cmd - fb` 派生 |
| 频域估计 | `dominant_frequency` `zero_crossing_frequency` `peak_spacing_frequency` `find_steady_window` `narrowband_line` `command_refresh_rate` | 频率类判据以「谱线绝对幅值 ÷ 误差动态 std」判定；落在指令刷新率及其谐波上的谱峰登记为「指令刷新成分、非对象响应」 |
| 等效参数 | `fit_second_order` `step_metrics` `estimate_second_order` `constant_accel_window` `error_analysis` `command_velocity` `command_acceleration` | `e ≈ a/ωn²` 只在 type-2（位置环 + 速度前馈）成立，不满足时报告写明 |
| FRF / 共振 | `compute_signals` | 扫频相干 H1 估计、阶次归因、谐振线识别 |
| 判据求值 | `load_rules` `diagnose` `evaluate_rules` `rules_th` | `SRV-01…07` 写在 `diagnose()` 里；`SRV-08…29` 是 `servo_rules.json` 表驱动 |
| 契约 / 报告 | `build_c3` `build_report` `run_diagnose` `run_synth` | — |
| 合成 / 模型 | `synth_step_2nd_order` `servo_2inertia_matrices` `freq_response` `closed_loop_response` `closed_loop_bandwidth_hz` `synth_step_2inertia` | 合成波形与真值**同源**，只能算自洽性验证 |

**五个必记的坑**（都在代码里有注释）：

1. **列名单字母别名不参与子串匹配**（`i`=电流、`t`=时间），否则 `time_ms` 会被当成电流通道。
2. **时间单位判定列名优先于数量级** —— 曾因把 800 ms 当秒，导致 ωn 差 1000 倍。
3. **跟随误差约定 `fe = cmd - fb`，正号 = 尚未追上**。
4. **`not_hit` 与 `not_evaluable` 不可合并**。
5. **置信度封顶**：`bandwidth_estimate` ≤0.6、`no_static_segment` ≤0.55、`counterfactual_unresolved` ≤0.6、`derived_velocity_feedback` ≤0.7。

### 7.4 证据分级（回答「凭什么信这个仓库」）

`coverage_ledger.json` 的 `meta.verification_levels` 给了 **5 档**：

1. **官方钉扎** —— 每条结论钉在官方一手件（手册章节 / 官方绑定行号 / PE 导出表），机器可复核。
2. **交叉审计** —— 被另一独立实现验证性执行核验过，审计报告在档。
3. **机器比对** —— 两个独立实现输出一致。
4. **自证** —— 只有实现方自己的测试/演示背书（同源，采信度最低）。
5. **未验证** —— 规格/知识存在但无实现、无对照。

**四类外部真值锚点**：

| 类别 | 内容 | 谁在守 |
|---|---|---|
| 协议标准 PDF | 7 份（Modbus×3 + FOCAS×2 + Snap7 + 三菱 FX5；**全部外置**到 `../mcopilot-external/vendor_docs/protocol_specs/`，仓内只留指针 + sha256） | `gate_anchors.py` 重算 sha256（外置件在位即核、不在位记 SKIP）+ 再提取抽查 + URL 存活性 |
| 厂商官方件 | `official_api/` 21 个 CSV：官方 C# 绑定、C 头文件、PE 导出表、手册索引、端子表、PDO 表 | `verify_trae_pinvoke.py` 三方对撞 + `test_binding_truth.py` |
| 真机 CSV | 5 份 `real_record`（DaRUS×3、Klipper、TwinCAT） | `.truth.json` + `PROVENANCE.md` |
| 独立基线复算 | 5 个 `verify_*.py`（不 import 被审代码） | 各脚本退出码非 0，可挂 CI |

**自洽性与外部证据的切分是显式的**：合成样本只证明检测逻辑自洽；README §七.7 / §七.9 明写「样例与规则同源」「仿真器自检只证明自洽」。

### 7.5 强绑定不变量（改了会断链）

1. **`csv_sha256` ↔ CSV** —— 改一个字节即断链（DaRUS 三份实测一致）。
2. **`anchors.json` ↔ 一手件** —— 15 条 `path → sha256 + size`，PDF/源码包/安装包任一被替换即红。非入库区条目（`out/` 本地产物、`../mcopilot-external/` 仓外原件）在干净检出上必然不在位：在位即核、缺位记 **SKIP** 并在汇总行喊出「当前不可自动复核」，**不判 FAIL**（那是把设计当缺件）。
3. **`modbus.json` 引文 ↔ 同源提取文本** —— `spec_ref.quote` 必须命中（53/53）。
