## 三、缺的信息：**1 项必须 + 2 项建议**（一次问齐）

### 必须（拿到才能上真机）

**M1. 现场在用卡的完整型号 + 配套接线盒型号 + 现场固件版本 + 要部署的 SDK 版本**

- 要问：
  1. 现场卡丝印上的**完整型号** —— 是 `DMC3C00S` / `DMC3C00-PCIe` / `DMC3800` / `DMC3600` / `DMC3400A`，
     还是 **DMC5000 系列（2210 / 2410 / 2610）**，还是 **DMC-E EtherCAT 总线卡**？
  2. 配套**接线盒型号** —— `ACC-X400` / `ACC-X400B` / `ACC3600` / `ACC3800` / `ACC-XC00` /
     `ACC2-X400B` / `ACC2-3600` / `ACC2-3800` / `ACC2-XC00`？是否加装 `ACC2-68B` 接线板、CAN-IO 扩展模块？
  3. 现场**固件版本**（`dmc_get_card_soft_version` 的返回值）与**部署要用的 `LTDMC.dll` 版本**
     （开发包目录名，如 `LTDMC_升级包_V2.5.7.23`）。
  4. 现场 **SEVON 端子接的是常闭还是常开**（决定哪个电平算「伺服使能」）。
- 为什么卡住：
  - 型号决定我们从**哪本附录**抄端子表（我们只有 DMC3000 系列的）；轴数、可�� IO 口数也随型号变。
  - 固件版本决定**哪些功能可用**：`dmc_set_output_status_repower`（断线重连后输出状态）需 **3XX201615 及以上**；
    限位回零（mode 10/11/12）需 **3XX201611 及以上**；旧固件上这些函数直接失败。
  - SDK 版本决定拷哪个 DLL —— 我们实测贵司有**三套同名 SDK**（见第四节），拷错版本会缺一整套功能。
  - SEVON 有效电平搞反 = **伺服使能判据反了**，这是安全信号。

### 建议（不急，但上机前要定）

**S1. SDK 版本 ↔ 固件版本的对应关系**

- 要问：① 本次交付对应的 `LTDMC.dll` 版本怎么查（`dmc_get_card_lib_version`？）；② `LTDMC.dll` 与固件版本
  是否一一对应；③ 手册里零散提到的最低固件要求（输出状态重连 3XX201615+、限位回零 3XX201611+）之外，
  常用函数还有哪些有最低固件版本要求。
- 为什么卡住：位数不匹配现场表现是「程序一开就崩」；固件不匹配表现是「函数返回 8（固件不支持）或不报错但行为不对」。
- **调用约定不用问，已确认**：官方 `LTDMC.h` 写的是 `DMC_API <类型> __stdcall <函数名>(...)` → `__stdcall`。

**S2. EMC（独立式控制器）的通用 IO 口号体系与端子表**

- **先说已经查清的、不用问的部分**：EMC **不是另一套函数库** —— 它用的是同一个 `LTDMC.dll`、
  同一套 `dmc_`/`nmc_` 函数名（官方 EMC 开发包 804 条声明里 `emc_` 前缀 **0 个**，
  **EMC 手册自己的 C 原型也全是 `dmc_`**）。差别只在**连接方式**：EMC 用
  `dmc_board_init_eth(IP)` 走以太网 TCP/IP（默认 IP 192.168.5.11，最多 254 台组网），
  DMC 插卡用 `dmc_board_init()` 走 PCI 枚举；以及**「卡号」的语义不同**（EMC 是链接号/控制器号）。
- 要问（只剩这两条）：① EMC 的**通用 IO 口号体系**与 DMC 是否通用
  （我们查到的 DMC3000 是口号 **0~15**、两组各 32 位位图；EMC 手册只给了
  **本体 12 入 12 出高速 IO**与总线上 16/16 的通用 IO，没给口号编号规则）；
  ② EMC 的**接线盒/端子表在哪本手册的哪一节**（EMC 手册附录 1 是「常见电路接线方法」，
  **没有端子表**；DMC-E 附录 1 才是本地接口端子表，但那是插卡用的）。
- 为什么卡住：IO 口号是**业务代码直接用到的编号**，猜错 = 读到别的口子的电平。
  端子表没有 = 接线时无从对照。

**S3. DMC-E / EMC 手册附录 3《常用 PDO 对象表》的 PDO 方向 + EMC 的急停接线（安全项）**

- **① PDO 方向存疑**：附录 3 表 F3.0 共 23 个 CiA402 对象，其中 **15 行的「PDO 映射」列与 CiA402 惯例相反**
  （6040 控制字标 `R_PDO`、6041 状态字标 `T_PDO`、6064 实际位置标 `T_PDO`、
  60FD 数字输入标 `T_PDO`、60FE 物理输出标 `R_PDO`…）。DMC-E 与 EMC 两本**逐行相同**。
  方向搞反 = 主站写从站、从站写主站，**表现是「轴不动」或「状态永远读不到」**。
  - 要问：表 F3.0 的 `T_PDO` / `R_PDO` 各自的准确含义，以及 6040 / 6041 / 6064 / 606C / 60FD / 60FE
    这几行到底该标哪个 —— **是笔误，还是我们对 T/R 的理解反了**？
  - 我们已经查到的：表本身手册自带（已抄成 23 行真值表，两列对照）；
    扩展 PDO 的 API 是 `nmc_write_rxpdo_extra` / `nmc_read_rxpdo_extra` / `nmc_read_txpdo_extra`；
    手册还给了「6041 状态字 bit10 = INP」的读法。**我们没有按这张表的 T/R 列写代码**，
    方向未确认前总线轴适配器不落地。
- **② EMC 没有专用 EMG 急停端子**：EMC 手册 2.2.1 原文建议「在本地通用输入口选一个口当 EMG，
  再用 IO 映射功能映射成急停」→ **现场若没做这个映射，等于没有急停**。
  - 要问：EMC 的急停推荐接线 —— 具体用哪个通用输入口号、IO 映射的完整配置步骤、
    **是否有独立硬接线急停端子**（若有请给端子号）。
- 为什么卡住：①卡住总线轴适配器的 PDO 读写方向与状态机读取；②卡住 EMC 现场急停接线的正确性（**安全项**）。

### 顺便提两处贵司手册的疏漏

**①《DMC3000 系列卡用户使用手册 V2.0》附录 11《运动控制函数索引》漏了两个函数**：
`dmc_get_stop_reason` 与 `dmc_clear_stop_reason` 在 **8.7 节正文里是有完整说明的**（p155~156），
但索引表（169 条）里没有列。我们照正文绑定，不影响使用；**麻烦补进索引**。

**②《EMC 系列总线型独立式控制器用户使用手册 V2.0》有 2 处函数名拼错**：
`dmc_emg_stop` 在**正文 6.3、8.16 的 C 原型、附录 4 索引三处**都写成 `dmc_EMG_stop`；
`dmc_axis_io_status` 在两处写成 `dmc_axis_IO_status`。
**PE 导出名大小写敏感** —— 照抄手册必然 `EntryPointNotFound`。
**硬证据**：EMC 自己的官方 C# 绑定、我们实测的三个版本 `LTDMC.dll` 导出表（32/64 位）**都只有全小写**。
（手册里另有 10 处 `position→positIOn` 这类差异，是 **EMC 手册 PDF 文本层的字形伪影**，不是笔误。）
**我们已按全小写绑定**；**麻烦贵司下一版改正这两处**，否则用户照手册写代码会直接崩。

## 五、我们的实现现状（供贵司核对，**不必回复**）

- DMC3000 适配器共 **37 条绑定，生成 35 条 P/Invoke**（另有 2 条**不生成**：
  `nmc_get_axis_state_machine` 是总线轴专用、`dmc_emc_...` 是占位提醒），
  **逐条与官方 `LTDMC.cs`、`LTDMC.h`、DLL 导出表、手册附录 11 对过**：函数名、参数个数、参数类型、
  `ref` 修饰、返回类型、调用约定全部一致。
- **保留参数一律传 0**（`ltc_mode` / `filter` / `triger_chunnel`），`all_enable` 只用 0 / 2 / 3。
- **伺服使能状态用 `dmc_read_sevon_pin` 读端子电平**，并提供 `ServoOnActiveLevel` 配置项（默认高电平），
  因为**有效电平取决于驱动器接法**。官方 `LTDMC.cs` 把 `dmc_get_sevon_enable` / `dmc_set_sevon_enable`
  标在「**内部使用（保留）**」下（返回值语义未公开）→ **我们不用**。
- **锁存通道由轴号决定**，`inPort` 只做 0~15 的范围校验与提示（ACC-X400：LTC0 = IN14、LTC1 = IN15）。
- **脉冲卡的轴状态用 `dmc_axis_io_status` 位图 + `dmc_check_done` 自行映射**到统一枚举。
- **高速比较通道号 0~3 与硬件 CMP0~CMP3 的对应是确定的**；CMP 端口落在哪个**物理端子**随接线盒型号而变，
  我们按现场接线盒型号核对端子（ACC-X400：CMP0/1 = CN23 的 PWM0/PWM1、CMP2/3 = CN21 的 OUT14/OUT15）。
- **脉冲卡适配器不调 `dmc_set_equiv` / `dmc_get_equiv`** —— 那两个是**总线卡/独立控制器**在控制器里设当量用的，
  调了会把当量改掉，位置整体差一个当量倍数。这条有回归测试钉住。
- **总线轴（EtherCAT）适配器暂不落地**：①PDO 读写方向待贵司确认（S3）；
  ②总线轴伺服使能序列手册未公开（安全动作不猜）→ 总线轴的 `Enable` 保持**显式失败**，
  不替贵司决定电机什么时候能动。
- **EMC 手册那两处大写笔误我们按全小写绑定**（`dmc_emg_stop` / `dmc_axis_io_status`），
  并已核对三个版本的 DLL 导出表 32/64 位都导得出。
- **官方 `LTDMC.h` 声明了、但 `LTDMC.dll` 导出表里没有的 6 个函数我们不绑**
  （`dmc_arc_move_center_angle_unit` / `dmc_cmd_buf_set_line_profile_ext` /
  `dmc_conti_da_curve_control` / `dmc_get_vector_s_profile_multicoor` /
  `dmc_lbs_trace_reset_config_object` / `dmc_set_vector_s_profile_multicoor`）——
  照抄头文件会 `EntryPointNotFound`。
