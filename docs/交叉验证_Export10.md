## 3. 这份数据的真实结构（判据基线，独立于 mcopilot 算出）

先建立基线，否则没法判断工具的数对不对。

**时基【元数据 + 独立】**：18651 点，`t = 0 … 18.650 s`，相邻间隔**恒为 1.000 ms**，`fs = 1000.0 Hz`，Nyquist = 500 Hz。
`out/crossval_export10_meta.json` → `time_axis.dt_unique_ms = [1.0]`、`sample_rate.measured_fs_hz = 1000.0`、`n_samples = 18651` —— 与独立复算一致。

**轨迹是三段【独立】**：

| 段 | 时间 | 指令 cmd | 反馈 fb | 速度 vel |
|---|---|---|---|---|
| A | 0 – 0.5 s | 恒 196.6009 | 16.8320 → 17.0389 | **+1.16954 mm/s** |
| B | 0.5 – 10.077 s | 恒 196.6009 | **恒 17.0389（死平，std 0.00011）** | **≡ 0** |
| C | 10.077 – 18.616 s | 197.1217 → 180.1114（阶梯下降，−2 mm/s） | 17.03 → ~0（同步跟随） | −2.105 … −0.356 mm/s |
| 尾 | 18.616 – 18.65 s | 恒 180.1114 | → −0.006 | −0.6658 mm/s |

**指令通道是 10 ms 阶梯波【独立】**：cmd 在 C 段共变化 **845 次**，相邻变化的间隔取值为 {9, 10, 11, 20, 30} ms，**标称刷新率 100 Hz**，而采样率是 1000 Hz。
→ 指令是 100 Hz 刷新的**阶梯**，不是连续轨迹。

**跟随误差【独立 / 元数据】**：
`mean = 179.812929`，`std = 0.270374`，`max|.| = 180.149520`，**动态/总量比 = 0.0015**（元数据 `fe_identity.dynamic_to_total_ratio`）。
→ 误差 **99.85% 是 180.11 mm 的常数偏置**，真正的动态误差只有 ±0.34 mm。

**⚠ 任务书给的 fe 统计量在本文件上复现不出来【元数据】**
任务书写 "mean=-0.9076, std=6.238, max|.|=851"。W1 的 meta `notes[3]`/`notes[4]` 已证明：那组数来自"把第 12 行的 `Port 851 Port 851…` 表头行当成第一条数据行"的污染解析（`data/validate_raw.py L260-L261`），上游自己的结论就是「⟹ 不成立」。本文件正确解析下的 cmd−fb 是 **mean=+179.8129 / std=0.2704 / max=180.1495**。
**这条必须先对齐，否则下面关于"跟随误差 180 mm"的判断会被误读成工具算错了——它没算错，它算的是"两个不同轴的位置之差"。**

**⚠ cmd/fb 这一对不是同一轴的指令/反馈【元数据】**
`meta.notes[5]` 明确判定：任务书指定的 `dPosition_asco → cmd_pos` / `dPosition_asco_enc → fb_pos` 这一对，"残差几乎全是常数偏置……**不是同一轴的指令/反馈，不能当跟踪误差读**"。
厂商自己用的三元组是 `dPosition_test_tar` / `dPosition_asco_enc` / `dPosition_diff`，其 cmd−fb 为 mean=0.9535 / std=0.0176 / max=1.170（`meta.cross_checks.vendor_triple`）。

**共振主通道缺失【元数据】**：规范 CSV 只有 `time_ms, cmd_pos, fb_pos, vel, vel_fb`；`dTorque_test` / `dTorque_load` / `dForce_*` 等 **29 个通道被 W1 按 C1 规则放进了 `meta.extra_channels`**（`meta.notes[1]`），**电流/转矩通道一个都没进规范 CSV**。
→ 按 axiscope 判据：**cur_q 缺失 → 共振主通道弱 → freq 类判据必须降级**。mcopilot servo 里**没有任何一条代码实现这个降级**。

**12–120 Hz（SRV-02 怀疑带）里到底有什么【独立】**：

| 通道 | 12–120 Hz 能量占比 | 前几号谱峰 |
|---|---|---|
| cmd (`dPosition_asco`) | **65.71 %** | 100.1 / 99.6 / 200.2 / 199.7 Hz |
| fb (`dPosition_asco_enc`) | **3.77 %** | 0.49 / 0.98 / 1.46 / 1.95 Hz（斜坡本身） |
| err = cmd − fb | **65.73 %** | 100.1 / 99.6 / 200.2 / 199.7 Hz（与 cmd 重合） |

→ **误差谱在怀疑带内的内容 100 % 来自指令刷新率（100 Hz）及其谐波，反馈通道里根本没有。** 这是一条纯指令侧的伪谱线。

### F-03 ★★★ 跟随误差报成 180 mm，无常数偏置识别 —— ②不适用 + 静默错误

**现象**
【工具】量化结果：

```
- 跟随误差峰值（含阶跃瞬间）：180.14952 mm
- 跟随误差 RMS：179.81313 mm
```

**判读**
- **算术没错**：`ea["peak"] = max|cmd−fb| = 180.14952`、`rms = 179.81313`，与【独立】复算逐位一致。**③碰巧对（就"数"而言）**。
- **但作为"跟随误差"是错的**：
  1. 标签 **"（含阶跃瞬间）"** 是错的——本波形**根本没有阶跃瞬间**（`is_step=False`），峰值纯粹来自 180.11 mm 常数偏置（`servo.py:921` 无条件写这个标签）。
  2. 动态部分只有 `std = 0.2704 mm` / `max(动态) = 0.3366 mm`，占 0.19%。**工具没有任何"常数偏置主导"的识别或降级**——`error_analysis`（`servo.py:514-552`）只算 peak/rms/mean/corr/CV，没有一个量把偏置和动态分开。
  3. 现场后果：一份写"跟随误差峰值 180 mm"的报告，会被读成"这台伺服失跟 180 mm"，实际结论是"**你把两个不同轴的位置通道配成了指令/反馈**"——这正是 `meta.notes[5]` 已经判定的事，而工具完全看不出来。
- **修法**：跟随误差统计前先做常数偏置分解，报告 mean 与 std；当 `std / peak` 低于阈值时标注"疑似两通道不同轴/存在常数偏置，不作为跟随误差读"。

这些数**一个都不能用**，但只因 `servo.py:438` 的 `is_step = moving_samples <= 2` 一票否决，`servo.py:566/567/570/582/604/669/680` 才没让它们进报告。**③碰巧对。**

守卫为什么"对"：`moving_samples = 845` 之所以不是 0，是因为**指令是 10 ms 阶梯、每跳都算一次变化**。
守卫为什么"脆"：
- 它只看"指令变化的样本数"，**不看波形形状**。一条"恒速段 + 单次阶跃"的真实轨迹，其指令变化样本数也 > 2 → 被误判为非阶跃；
- 反过来，一条**指令刷新阶梯极密**但物理上是单次阶跃的波形，会被判成 `is_step=True` → **100% 超调 / 8.573 s 整定时间 / 0 s 峰值时间会原样进报告**。

**具体是怎么算错的**：
- `target = median(clean[-k:])`（`servo.py:383`，k = n//10 = 1865）→ 取到 C 段斜坡中段的 fb，**根本不是"到位值"**；
- `start` 取阶跃前 20 ms 的 fb 中位数（`servo.py:400-401`）→ 取到 B 段死平值 17.0389；
- `peak_i = argmax(clean)`（`servo.py:407`）→ 取到**全程 fb 的全局最大值**，位置在 t ≈ 0.5 s，**在"阶跃"之前**；
- 于是 `overshoot = (17.0389 − 1.7632)/15.2757 = 1.000`（正好 100 %），`tp = max(0, t[peak] − step_t) = 0`（被 `servo.py:410` 的 `max(0.0, …)` 夹成 0）；
- `settle_time` 从尾部往前扫（`servo.py:414-417`）→ 8.573 s。

**判读补充**：`servo.py:390-391` 用的是 `w.n`（原始长度）而不是 `len(clean)`，而 `clean` 过滤了 NaN——本次无 NaN 所以没暴露，但这是同一处的一个隐患。

### F-05 ★★★ "阶跃时刻"取成了指令刷新阶梯 —— ①真错

**现象**
`servo.py:389-397` 用"**指令最大跳变**"定位阶跃时刻：

```python
jumps = [(abs(w.cmd[i] - w.cmd[i-1]), w.t[i]) for i in range(1, w.n) …]
best_jump = max(jumps, key=lambda j: j[0])
if best_jump[0] > 0:
    step_t = best_jump[1]
```

【独立】本数据的最大 |Δcmd| = **0.5208 mm @ t = 10.077 s**，而它旁边的一跳是 −0.0337、−0.0133、−0.0129 …
→ **0.5208 是指令 100 Hz 阶梯的第一跳（斜坡起点的刷新跳变），不是被控对象的阶跃指令。**
工具把一个"指令刷新伪跳变"当成了"阶跃响应激励"。

**判读**
真实伺服现场导出的指令通道，**只要上位机是"周期性刷新目标"而不是"收到一帧就跳一次"，这个检测就一定选错**。
正确做法是**边沿检测**：阶跃前若干 ms 内 cmd 方差≈0（指令恒定），随后出现一个显著大于指令刷新噪声的跳变。当前实现没有"指令恒定段"的前置条件，也没有"刷新噪声"的量级概念。

### F-06 ★★★ SRV-05 的两个判据在真实数据上都失效 —— ①真错 + 漏报

**现象**
【工具】`error_analysis`：

```
vel_corr     = -0.9843346760073217     （阈值 type1_vel_corr_min = 0.85）
vel_ratio_cv = 0.4218538944610161       （阈值 type1_vel_ratio_cv_max = 0.25）
vel_slope    = -0.2630460514386923
→ SRV-05 不触发
```

**判读 —— 判据 1：整段相关系数是簇间伪相关**

`servo.py:528-540` 在**整段**上算 Pearson。【独立】分段复算：

| 段 | vel | e 均值 | e std | **corr(e, v)** |
|---|---|---|---|---|
| A 0–0.5 s | +1.1695 | 179.5988 | 0.06116 | +0.7758 |
| B 0.5–10.077 s | ≡ 0（零方差） | 179.5620 | 0.00011 | 不可定义 |
| C 10.077–18.65 s | −2.105 … −0.356 | 180.1057 | 0.00738 | **−0.0499** |
| **整段** | | | | **−0.9843** |

整段相关几乎全部由**簇间均值差**贡献：vel 簇均值 +0.44 / 0 / −1.99，对应 e 簇均值 179.599 / 179.562 / 180.106——"vel 越负、e 的簇均值越大"，相关系数必然逼近 −1。
**唯一有真实运动的 C 段内部，corr(e, v) 只有 −0.05。**
→ 在**多运动段**数据上（正是与自造阶跃样例的根本差别），整段相关系数天然饱和到 ±1，**不携带任何 type-1 信息**。

**判读 —— 判据 1 还有第二个坑：单侧符号门**

`servo.py:656`：`ea["vel_corr"] > th["type1_vel_corr_min"]`，**只接受正相关**。
而按 `servo.py:73` 的约定 `e = cmd − fb`（正 = 还没追上），**反向运动时误差与速度天然反号**。
本数据 vel 全程 ≤ +1.17 且主段为负 → `vel_corr = −0.984` → **SRV-05 对反向运动永久失明**（应取 `abs()`）。

**判读 —— 判据 2：比值 CV 被常数偏置 + 近恒定速度污染**

`servo.py:545`：`ratios = [e / v for v, e in pairs if abs(v) > 0.5 * vmax]` —— 用的是**含 180 mm 常数偏置的原始 e**。

【独立】C 段（近恒速 v ≈ −2）上：`e/v` 中位数 = **−89.99 mm/(mm/s)**，CV = **0.0643**（< 0.25）→ 工具会判"比值恒定 → 疑似 type-1"。
**但"180.11 ÷ 近恒定的 −2"本来就近似恒定**，这个 CV 不构成任何 type-1 证据；去偏置后 CV = 0.0679，也一样。而 C 段内部 corr(e,v) = −0.05 说明**这里根本不存在速度成正比的误差**。
→ 判据 2 在"大偏置 + 近恒速"下**不可证伪**。

**综合判读**
- 本数据 SRV-05 不触发，但**它现在的"沉默"是数据巧合，不是判据可靠**：把开头 0.5 s 暖机段切掉，CV 立刻从 0.4218 掉到 **0.0643**、corr 变成 **−0.9958**——**只要运动方向反过来、且头部没有暖机段，SRV-05 就会报"高：疑似缺速度前馈"**。
- **漏报**：这份数据里，SRV-05 报不出任何东西（两个门都堵死），而它报不出的是 **type-1/type-2 这个真实待判问题**。
- **误报**：在反向运动的数据上，一旦 CV 判据被绕过（例如有人把 `vel_ratio_cv` 的阈值调松，或数据只有一段恒速），就会报一条"高"级别的假 type-1。

### F-07 ★★★ 尾段误差主频 0.49 Hz = DFT 最低 bin，且窗口跨越轨迹起点 —— ①真错（幻觉）

**现象**
【工具】量化结果最后一行：

```
- 尾段误差主频：0.49 Hz（突出度 238）
```

**判读 —— 为什么是 0.49 Hz**
`dominant_frequency`（`servo.py:163-210`）：

- `hi = min(fs/2, 400.0) = 400`（`servo.py:186`）
- `kmin = max(1, int(0.5 · n/fs)) = 1`（`servo.py:188`）
- `n = min(nfft=2048, len(tail)=9326) = 2048` → **频率分辨率 fs/n = 1000/2048 = 0.48828125 Hz**
- 报出的主频 = **0.48828125 Hz = 1000/2048，正好落在 DFT 的最低可分辨 bin（k=1）**

→ **这是残差趋势，不是任何物理振荡。** 报告却给它标了"突出度 238"，读起来像一个非常强的稳定振荡。
工具**没有对"主频落在最低/最高 bin"做任何提示**，也没有对"频率分辨率"做任何说明。

**判读 —— 窗口根本不是"稳态"**
`servo.py:591`：`tail = err_sig[len(err_sig) // 2:]` → 起点 t = **9.325 s**；
`dominant_frequency` 只取前 `nfft` 点 → **实际频谱窗口 = t ∈ [9.325, 11.373] s**，
**跨过了 10.077 s 的轨迹起点**。
`servo.py:585-587` 的注释明说"稳态频谱：只看尾段的误差……只有尾段仍在持续振荡时，频谱峰才是真的持续振荡频率"——**但代码没有校验尾段是否真的稳态**。

**判读 —— 真正的静止尾段里是什么**
【独立】同一函数，换成真正静止的尾段：

| 窗口 | 主频 | 突出度 |
|---|---|---|
| 工具用的 tail[0:2048]（t 9.325–11.373 s，跨轨迹起点） | 0.488 Hz | 237.6 |
| 真正静止尾段 err[−2048:]（t 16.60–18.65 s） | **100.098 Hz** | 48.3 |
| 斜坡段 err[12000:14048]（t 12–14 s） | **100.098 Hz** | 71.9 |

**判读 —— 100 Hz 是什么**
指令刷新率是 100 Hz（§3）。逐通道验谱【独立】：

- cmd 通道 12–120 Hz 能量占比 **65.71 %**，峰在 100.1 / 99.6 / 200.2 / 199.7 Hz；
- fb 通道 12–120 Hz 能量占比 **3.77 %**，峰全在 0.49 / 0.98 / 1.46 / 1.95 Hz（斜坡本身），**没有 100 Hz**；
- err 通道 65.73 %，峰与 cmd **完全重合**。

→ **误差谱在怀疑带内的内容 100 % 是指令刷新伪谱线；反馈侧完全没有这个成分。**
幅值 0.00316 mm，相对 0.27 mm 的动态误差只有 **1.2 %**——物理上毫无意义。

**判读 —— 关于"超带宽幻觉"这一项**
本次**没有**出现超 Nyquist 的数（`fmax` 被 `min(fs/2, 400)` 夹住，报出的 0.49 Hz 远低于 500 Hz）。
**但带宽幻觉的真正形态在这里是"把一条指令刷新伪谱线 / 一条残差趋势，报成一个带物理含义的频率 + 突出度 238"**，而不是超 Nyquist。

### 误报规则（在这份数据上"差一点"就会误报）
1. **SRV-02** —— 若判据改用 DFT 主频：100.1 Hz 落在 12–120 Hz 带内 → 报"高：机械谐振"。**一个由指令刷新率制造的假谐振**。
2. **SRV-05** —— 只要数据头部没有那段 0.5 s 暖机段（CV 0.4218 → 0.0643），或运动方向为正（符号门改 `abs()`），就会报"高：疑似缺速度前馈"。**本数据的"沉默"是头部偶然段落的功劳。**
3. **SRV-01** —— 只要 `is_step` 守卫失效（指令刷新阶梯密集但物理上是单次阶跃的真实轨迹），就报"超调 100 %"。

### 漏报规则（在这份数据上"本该报却没报"）
1. **SRV-02** —— 误差谱里**确实**有 12–120 Hz 的成分（占带内能量 65.7 %），只是来源是指令刷新而非机械谐振；工具两类都看不见。**若机械谐振真的存在，本工具在这份数据上同样会漏**（因为 `is_step=False` 直接把振铃路径关掉了）。
2. **SRV-05** —— type-1/type-2 这个真实待判问题，两个判据全废，**一条有用信息都给不出**。
3. **SRV-07** —— "末段不收敛"这类结论需要 `is_step`，在真实连续轨迹上永远出不来。
4. **一个工具压根没有的漏报**：cmd/fb 通道语义错配（常数偏置 180 mm，动态占比 0.15 %）。**这恰恰是这份数据最该报的一条**，而工具没有任何机制能发现它。

## 8. mcopilot servo 支的同源自证风险评估

### 8.1 自测语料长什么样

仓库自带的 3 个伺服样例全部由 **`make_samples.py` 合成**（`make_samples.py:349` 的 `FS = 2000.0`），
写 CSV 的代码在 `make_samples.py:352` 的 `_write_servo`：

```python
lines = ["time_ms,cmd_pos,fb_pos,err,vel"]
```

（`servo.py:1019` 的 `run_synth` 写的是同一行表头 —— 两条生成路径殊途同归，**表头恒定这件事是结构性的**。）

三个样例的表头逐字相同：**`time_ms,cmd_pos,fb_pos,err,vel`**【工具】
（`samples/servo/case_a_normal.csv`、`case_b_resonance.csv`、`case_c_no_feedforward.csv`）。
`truth.json` 里给的独立真值只有 `model / wn / zeta / bandwidth_hz / resonance_hz / resonance_peak`（`servo.py:1002-1013`），
以及 `case_b_resonance.truth.json` 里那个**由合成器自己注入的** 35 Hz 模态：

```json
{ "case": "柔性传动谐振", "loop_wn_rad_s": 100.0, "loop_zeta": 0.8,
  "ringing_hz": 35.0, "ringing_amp_mm": 2.0, "ringing_decay_per_s": 8.0,
  "expect_findings": ["SRV-02"],
  "note": "机械谐振模态 35 Hz 落在 12~120 Hz 疑似区间，SRV-02 应命中" }
```

**这份真值的要害是：那个 35 Hz 是生成器亲手加进去的正弦，工具当然能检出它。**
真实数据里 12–120 Hz 带内唯一的成分是 100 Hz 指令刷新伪谱线，**而它不在反馈通道里** —— 这两件事在自测里无法区分。

### 8.2 因此，下面这些结论在自造样例上"必然检出"，在真实数据上完全不成立

| # | 自造样例上"必然成立"的结论 | 在 Export10 上为什么不成立 | 后果 |
|---|---|---|---|
| 1 | **「画图一定能成功」** —— 样例必有 `err` 列，`w.err or []` 永远非空 | 真实 CSV（CODESYS Scope 规范 CSV / 厂商导出）**普遍没有 err 列**（err 是派生量） | **F-01 崩溃，零产出**。这是最贵的一条：自测永远看不到它 |
| 2 | **「`is_step` 守卫有效」** —— 合成样例的指令是"恒定→跳一次"，`moving_samples ≤ 2` 恒成立 | 真实轨迹指令连续变化（Export10 = 845 次）；守卫在这里是靠"够大"才挡住，不是靠判据正确 | 自测**从未检验过守卫会不会误挡真实单次阶跃**，也从未检验过它挡不住时会输出什么（100 % 超调 / 8.573 s 整定时间） |
| 3 | **「频率判据能给出物理上说得通的峰」** —— 合成波形是解析的、无噪声、无指令刷新阶梯 | 真实波形里有 **100 Hz 指令刷新伪谱线**（带内能量 65.7 %），且落进 SRV-02 的 12–120 Hz 怀疑带 | 自测**没有"指令刷新率"这个概念**，永远测不出"SRV-02 会因刷新率误报" |
| 4 | **「err-vel 相关性是干净的 type-1 签名」** —— 合成 type-1 就是 e = k·v，单调、单一簇 | 真实数据是**多簇**（+1.17 / 0 / −2 mm/s），整段相关被簇间均值差拉到 −0.984，段内只有 −0.05 | 自测**测不出"整段相关在多运动段上是伪相关"**，也测不出"单侧符号门让反向运动永久失明" |
| 5 | **「跟随误差是小量」** —— 合成样例阶跃幅度 100 mm，稳态误差趋近 0 | 真实数据跟随误差 **180 mm 常数偏置 + 0.27 mm 动态**（动态占比 0.15 %） | 自测**测不出"常数偏置主导"这个形态**，工具因此把 180 mm 直接当跟随误差报出去 |
| 6 | **「频段覆盖 = 采样率决定」** —— 合成样例 fs=2000 Hz（`make_samples.py:349` 的 `FS = 2000.0`），1/3、1/2 的刷新率永远不会碰 | Export10 fs=1000 Hz，**刷新率 100 Hz 正好在怀疑带内** | 采样率与指令刷新率的关系（整除关系）**在自测里不可能暴露** |
| 7 | **「SRV-02 在谐振样例上必然检出」** —— `case_b_resonance.truth.json` 的真值写着 `"ringing_hz": 35.0`、`"expect_findings": ["SRV-02"]`，注记"机械谐振模态 35 Hz 落在 12~120 Hz 疑似区间，SRV-02 应命中"。**这 35 Hz 是合成器自己注入进去的正弦模态** | Export10 里 12–120 Hz 带内唯一的成分是 **100 Hz 指令刷新伪谱线**，而它**不在反馈通道里**（fb 带内占比 3.77 %） | 自测的谐振是"注入进去的已知模态"，检出它是必然的；**真实谐振 vs 伪谱线的区分能力，自测为零** |
| 8 | **「两列就是同一轴的指令/反馈」** —— 合成样例天然如此 | Export10 的 `dPosition_asco` / `dPosition_asco_enc` **不是同一轴**（`meta.notes[5]`） | 自测**测不出"通道语义错配"**，而这恰恰是这份数据最该报的一条 |
| 9 | **「`truth.json` 能覆盖所有结论」** —— 真值只有 ωn/ζ/带宽/谐振峰/35 Hz 模态 | 真值里**没有任何一项**覆盖：多运动段、指令刷新阶梯、通道语义、常数偏置、缺转矩通道 | 这些正是真实数据上出问题的地方，**自测的"验证通过"与真实可用性之间没有对应关系** |

### 8.3 结论

**mcopilot servo 支的自测只验证了"合成器 ↔ 估计器"的闭环一致性，没有验证"真实记录 ↔ 估计器"的可用性。**
更精确地说：自测样例让**所有前提条件天然成立**（有 err 列、指令是单次阶跃、误差是小量、两列同轴、无刷新率伪谱线、有转矩通道……），
而真实数据**几乎把每一条前提都推翻了**，而工具**没有一条前提检查**——它假定前提成立，然后照常输出结论。

**一个能落地的自检建议**：把 `samples/servo/` 的样例生成器扩到能产出 **①无 err 列 ②指令为 100 Hz 阶梯 ③多运动段 ④常数偏置主导 ⑤无转矩列 ⑥反向运动** 这 6 种形态，
每种都断言"**不崩 + 明确声明该判据不适用**"。这 6 条断言在当前代码上**全部会失败**。

## 9. 建议修复清单（按优先级；本报告未改任何源码）

### P0 —— 先让它别崩、别撒谎

1. **`servo.py:969`**：`w.err or []` → `w.error_signal()`。
   同时 `chart.py:88` 前加 `assert len(err) == len(t)`，让长度不匹配在源头报而不是在 matplotlib 里报。

2. **`servo.py:865-876`**：结论分支改为**先判 `is_step`、再判 findings**。
   允许写"未发现异常特征"的前提是**同时声明"有 N 条判据因前提不满足未执行"**。
3. **报告里显式列出未执行的判据编号**（`servo.py:887-940`）：例如"本次未执行 SRV-01/02/06/07（波形非单次阶跃）、SRV-03/04（未提供 --accel 且无可辨识二阶参数）、freq 类（无转矩/电流通道，共振主通道缺失 → 按 axiscope 判据降级为不可判）"。

### P1 —— 把口径改对

4. **`servo.py:389-397`**：阶跃起点改为**边沿检测**（阶跃前 N ms 内 cmd 方差≈0 → 随后出现显著跳变），
   并引入"指令刷新噪声"量级概念（相邻变化间隔中位数 vs 采样周期），把 10 ms 阶梯识别出来并拒绝用它当阶跃。
5. **`servo.py:514-552`**：跟随误差统计做**常数偏置分解**——报告 mean / std / 动态占比；
   当 `std/peak < 阈值` 时标注"疑似两通道不同轴或存在常数偏置，**不作为跟随误差读**"，并把标签"（含阶跃瞬间）"改成随 `is_step` 自适应。
6. **`servo.py:528-540`**：`vel_corr` 改为**按指令运动段分段计算**并取 `abs()`；报告里同时给出段内相关与段间结构。
7. **`servo.py:544-549`**：比值 CV 用**去偏置**误差 `(e − median(e))`；并在报告里说明该比值的物理含义与成立前提。
8. **`servo.py:586-592`**：频谱窗口必须落在**真正的稳态段**（指令与速度均恒定的最后一个连续段）；窗口若跨运动事件则降级为"不适用"；
   报告里必须打印 `fs` / `nfft` / **频率分辨率 fs/nfft**，并在主频落在最低/最高 bin 时给出提示。

### P2 —— 补齐降级与边界

9. **`servo.py:41` + `86-90`**：删除 `COL_ALIASES["torque"]` 的单字母别名 `"i"`，或把子串兜底限制为长度 ≥ 3 的别名。
10. **`servo.py:163-210`（`dominant_frequency`）+ `servo.py:614-621`（SRV-02）**：给频率判据加三道门 ——
    (a) 谱峰必须显著高于噪声底；(b) 剔除与**指令刷新率及其谐波**重合的 bin（刷新率可从 cmd 通道直接测得）；
    (c) 通道必须含足够的动态内容，否则按 axiscope 判据降级为"**不可判**"。
11. **`servo.py:467-511`**：`constant_accel_window` 拒绝长度 < 20 点的窗口。
12. **`servo.py:955`**："未做的对比（原因）"的触发条件改为"**给了 `--accel` 但没做成对比**"。
13. **`servo.py:967-970`**：图表标题按 `is_step` 自适应；非阶跃时**不画 target 线**；误差子图标注常数偏置。
