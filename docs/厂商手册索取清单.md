   参数是 `(轴号, 起始点, 结束点, 表倍率, 距离)`，**不携带表内容** → 凸轮表在控制器侧。
   卡住：`ftablemulti`（表倍率）与 `fDistance`（距离）的**确切语义与取值范围**、
   凸轮表**段数上限**、凸轮表怎么建（CAM 指令？BASIC 脚本？存在哪），
   以及 `ZAux_Direct_Cambox` 的 `ilinkaxis` / `ioption` / `flinkstartpos` **到底管什么** ——
   倍率填错，从轴就按错误的比例走位。
9. **固高 GTS 这条线是否真的没有电子凸轮能力、有无替代方案**。
   我方已确认：官方 C# 绑定 473 条、官方 C 头文件 535 条、`gts.dll` 的 32 位与 64 位 PE 导出表 ——
   "cam" 符号**各 0 个**；主从同步只有「跟随段 + 事件交叉」
   （`GT_BufFollowStart` / `GT_BufFollowNext` / `GT_BufFollowReturn` / `GT_BufFollowEventCross`）
   与电子齿轮（`GT_SetGearRatio` / `GT_GearStart`）。
   用途：**如果贵司有别的产品线支持电子凸轮**（例如 GEN 系列的 `GTN_` 前缀，或其他系列），
   请指明是**哪个产品线、哪本手册、哪些函数** —— 我们按「换卡不改代码」设计，
   GTS 这条线现在只能走跟随段，**语义与查表凸轮不同，不能平移**。
   卡住：若确实没有凸轮表，我们就按跟随段 + 事件交叉方案落地，但现场验收口径要跟着换。
10. **凸轮相关的过冲 / 冲击官方限值或建议值**（三家通用）。
    我方已确认：三家官方件里**都没有**给出「段接缝速度阶跃」或「从轴加速度突变」的官方限值。
    我们自定的口径是「**阶跃速度 ÷ 从轴速度上限** > 20% 判高危、> 5% 判注意」
    （`knowledge/cam_rules.json` 的 `velocity_step_limit_ratio` / `velocity_step_warn_ratio`）——
    **这是我们自己的口径，不是贵司指标**。
    用途：现场验收需要一个能写进检验单的数。
    卡住：没有官方值时，我们只能把这一项标成「待确认」，不会拿自定口径冒充贵司指标。
11. **凸轮与其它功能的并发**（三家通用）：凸轮执行期间能不能同时插补？能不能同时开硬件比较输出
    （飞拍）？凸轮表能不能在运行中热更新（`dmc_cam_write_points` 运行时改表会怎样）？
    用途：飞拍触发点常常就落在凸轮段上 —— 两件事能不能同时开，
    决定飞拍触发源取指令位置还是反馈位置。
    卡住：运行中改表如果会跳变，这是安全动作，必须先问清。
