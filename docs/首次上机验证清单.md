# 首次上机验证清单

> **这份清单的定位**：适配层在桌面阶段能验证的都验证了（编译、签名、换算、状态机），
> 但**厂商语义（方向/停止方式/IO 电平）和物理接线只能上机确认**。
> 这份清单把「上机第一小时怎么花」排成**分级递进**：上一级不过，绝不进入下一级。
>
> 配套：`docs/厂商手册索取清单.md`（问厂商）、`out/csharp/MotionContractTests.cs`（自动化那部分）。

---

## 上机前（不通电运动）

- [ ] 急停按钮**手动按一下**确认真的停（不要相信 PLC 状态，要试物理急停）
- [ ] 软限位已配置（这是最后一道防线，比限位开关可靠）
- [ ] 伺服使能信号（SERVO ON）已接、驱动器无报警
- [ ] 记录**当前机械位置**（拍照存档），后面要核对
- [ ] 手放在急停上，或者把点动速度调到 ≤ 5 mm/s

> ⚠ **L2 之前不要解除任何限位保护。** 方向写反是这类代码最典型的失效模式：
> 它不报错、不写日志，轴直接往反方向走。

## L0 · 桌面自检（不接运动，**先证明判据是通的**）

**做什么**：这一级**不证明设备是好的**，只证明两件事 —— ① 工具链本身跑得通（读表 → 生成 → 判定 → 出报告）；
② 判据本身是对的（该报的报得出来、不该报的别乱报）。

**为什么放在最前面**：凸轮的典型故障在现场表现为机台「咔哒」声 + 伺服跟随误差报警，
**凸轮表本身看不出任何问题** —— 表上每段都是「合法」的直线，问题出在段与段之间。
判据要是错的，现场根本分不清是表的锅还是机械的锅。

| 做什么 | 命令 | 合格判据 | 不合格先查什么 |
|---|---|---|---|
| 生成一张基准凸轮表 | `mcopilot cam plan --master-travel 360 --slave-travel 8 --segments 4 --master-v 360 --slave-v-max 300 --slave-a-max 2000` | 报告结论 **「通过：未发现超限或阶跃问题」**；产出 `out/cam_plan_table.csv` + `out/cam_plan_table.json`（表头 `master,slave`）；最大段间阶跃 4.000 mm/s（占从轴速度上限 1%）| 报「⚠ 有段做不出来」→ **是物理不满足，不是工具坏了**：`时间不够` = 主轴在这一段给的时间不够；`不可行` = 从轴速度上限低于完成这一段所需的最低速度 → 改 `--master-v` / `--segments` / `--slave-a-max` 重来 |
| 用样例表验判据（**这张表是故意留了阶跃的**）| `mcopilot cam check samples\cam\pick_place_cam.csv --master-v 360 --master-a 200 --slave-v-max 300 --slave-a-max 2000 --slave-travel 120 --master-unit deg` | 结论 **「不通过：有必须先处理的问题」**；CAM-04 高危落在**第 7 段断点**（主轴 270 处）：阶跃 **72.000 mm/s**、占从轴速度上限 **24%**（阈值 20%）、过渡段主轴至少 **0.0360**（= 72 ÷ 2000）| 判成「通过」→ 判据没生效：先查 `--slave-v-max` 给了没（不给则严重度判不了，只会报「无法判严重度」）；再查严重度是不是按「阶跃速度 ÷ **从轴速度上限**」算的（**不是** ÷ 峰值速度 —— 峰值速度很小时除以它会放大成假警报）|
| 看清楚「最严重的接缝在哪」 | 同一份报告的「段间接缝（机械冲击的来源）」一节 | 每个断点都列出斜率、斜率差 Δk、阶跃 Δv、占从轴速度上限、**过渡段最小主轴宽度**；样例表里最差的一处是主轴 270 处的第 7 段 | 最差接缝与「印象里的机台」对不上 → 查主轴坐标单位（deg？mm？pulse？）与主轴实际转速：主轴坐标写错单位，斜率整体错，阶跃跟着错 |
| 确认你这台卡属于哪种凸轮语义 | `mcopilot cam caps` | 「可从上位机整表下发」**只有雷赛**（`dmc_cam_table_unit`）；正运动只有 `ZAux_Direct_Cam` / `ZAux_Direct_Cambox`（**只引用表的区间，不携带表内容**）；固高那一栏是**没有** | 与手里的卡对不上 → 确认现场到底是哪家控制器、哪条产品线（固高 GEN 系列是另一套 `GTN_` 签名，不在本 SDK 包内）|
| 把参数口径填对 | `--master-v` 主轴**实际**转速（不是额定值）｜`--master-a` 主轴加速度｜`--slave-v-max` **从轴**速度上限（判严重度用它）｜`--slave-a-max` **从轴**加速度上限（算过渡段宽度用它）｜`--slave-travel` 从轴行程 | 给了 `--master-a` 时报告会多一条 CAM-08 提醒：主轴在凸轮生效区间内加减速 → 从轴时序整体偏移 | 从轴上限填成主轴的 → 严重度整体偏；主轴速度填额定值 → 阶跃被高估；`--slave-v-max` 漏填 → 只能算阶跃绝对值，判不了严重度 |

> 📌 **严重度口径只有一个，别记错**（`knowledge/cam_rules.json` → `checks[]` 里 `id = CAM-04` 的 `severity` 字段）：
> 判据是**阶跃速度 ÷ 从轴速度上限** —— `velocity_step_limit_ratio` = **0.20** 判**高危**、
> `velocity_step_warn_ratio` = **0.05** 判**注意**，判定是**严格大于**。
> 样例表第 8 段（主轴 300 处）的阶跃是 60.000 mm/s = 20.0%，**压线不判高危**，
> 所以报告里应当只出现**一条** CAM-04 高危（第 7 段）。
> ⚠ `defaults.velocity_step_ratio`（0.15）与 `defaults.accel_headroom`（1.0）**当前不参与判定**，别拿它们当阈值讲。

> **本级验不了、必须留到现场的**（这一栏**不许打勾**，留到 L7）：
> 主从同步精度、跟随误差实测曲线、转矩尖峰、机台异响、凸轮表掉电保持、
> 从轴实际轨迹与表是否一致，以及厂商侧的凸轮表**最大点数 / 表号数量 / `SrcMode` 取值 / 挺杆规则**
> （官方 C# 绑定只给签名，**DMC3000 手册没有凸轮函数章节** → 已列入 `docs/厂商手册索取清单.md`，**待厂商确认**）。

## L1 · 连接与读值（不动电机）

**做什么**：打开控制器，读轴状态、读当前位置、读一个输入点。

| 看什么 | 正常 | 不正常说明 |
|---|---|---|
| `Open()` 不抛异常 | 连接成功 | 抛异常 → 看错误码：驱动未装 / DLL 位数不符 / IP 不通 |
| `GetState()` | 状态机值落在 0~7 | 读不到 → 状态机函数不对（**雷赛脉冲卡根本没有轴状态机函数**：官方绑定里唯一的 `nmc_get_axis_state_machine` 是 EtherCAT 总线轴专用，我们用手册 8.7 的 `dmc_axis_io_status` 位图 + `dmc_check_done` 自行映射 —— **雷赛总线卡（EtherCAT）我们目前不落地适配器**：DMC-E / EMC 手册附录 3 表 F3.0 里 15 行 PDO 方向与 CiA402 惯例相反（待厂商确认），且手册没写总线轴的使能序列 → 状态机读取与 `Enable` 都保持显式失败） |
| `GetPositionMm()` | 接近 0 或已知位置 | 差 1000 倍 → **脉冲当量 UNITS 设错** |
| `GetStopReason()` | 0 | 非 0 → 控制器本身有历史报警，先清 |
| `ReadInput(0)` | 与面板指示灯一致 | 不一致 → **IO 位号映射错**（查 FAE 清单 B2） |
| `HasRealFeedback(axis)` | 告诉你这一轴到底有没有真反馈 | 声称有真反馈、但读数恒等于指令位置 → 反馈没接上或 ATYPE 配错 |
| DLL 与位数 | 加载成功、位数匹配 | `DllNotFound` / `EntryPointNotFound` → **DLL 名或位数错**（雷赛官方绑定用 **`LTDMC.dll`**；正运动 **`zauxdll.dll`（ZAux_* 层）+ `zmotion.dll`（低层库）**，两个都要在输出目录）。改 `knowledge/sdks/*.json` 的 `dll` 字段重新生成 |

**怎么停**：不涉及运动，直接拔。

### 反馈真伪怎么定（正运动：ATYPE 决定 MPOS 的来源）

| ATYPE | 轴类型 | MPOS 实际来源 | `HasRealFeedback` |
|---|---|---|---|
| 0 | 虚拟轴 | 无 | false |
| 1 | 脉冲轴 | **DPOS 的副本** | false |
| 4 / 5 | 带编码器反馈的脉冲轴 | 编码器 | true |
| 7 | 资料归入脉冲轴/虚拟轴一类 | DPOS 的副本 | false |
| 21 | 振镜轴 | 公开资料未说明 | false（保守处理） |
| 50 | RTEX 总线轴 | 驱动器 0x6064 | true |
| 65 / 66 / 67 | EtherCAT 总线轴（主站下发，能力以从站为准） | 驱动器 0x6064 | true |

> ⚠ **脉冲轴上跟随误差恒为 0 是正常的，不是适配器写错了。** 契约测试已按 `HasRealFeedback` 分流，不会在开环轴上误报。

**不依赖 ATYPE 配对的现场判别法**：伺服未使能时**用手转电机轴**，看 `GetFeedbackMm()` 读数变不变：
不变 = 假反馈（MPOS 只是 DPOS 副本），要按开环轴对待；
变 = 真反馈，跟随误差、整定、飞拍补偿才有依据。

**总线轴的交叉验证（可选）**：用正运动适配器的 `ReadBusObject(...)` 读从站的 `0x6064`（实际位置），
与 `GetMpos()` 的读数对照 —— 两者不等说明 ATYPE 配错或反馈通道没接上。
（`0x6064` 是驱动器原始计数，与 MPOS 的换算关系取决于电子齿轮，需现场核对。）

**雷赛**：`dmc_get_encoder` 是独立计数通道，**接了编码器才有效**（没接恒为 0）。
把适配器的 `EncoderFeedbackWired` 按现场接线置成 `true` / `false`，别靠代码猜。

## L2 · 低速点动（**方向，最高危**）

**做什么**：点动速度 ≤ 5 mm/s，每次只点 0.5 秒，正反各一次。

```
Jog(axis, +5.0)  →  位置应该【增加】
Jog(axis, -5.0)  →  位置应该【减少】
```

| 现象 | 结论 | 处理 |
|---|---|---|
| 位置增加/减少，方向对 | ✅ 方向编码正确 | 记录到现场配置单 |
| **方向反了** | 点动方向编码错 | **立刻停机**。核对：雷赛 `dmc_vmove` 的 dir（0 负/1 正，**公开资料有相反写法**）、正运动 `Single_Vmove`（−1/1）。改 `knowledge/sdks/*.json` 后重新生成，**不要在业务层打补丁** |
| 完全不动 | 不是方向问题 | 查：使能？伺服报警？软限位已触发？速度单位是 0？ |
| 动一下就停 | 碰到限位或软限位 | 正常保护动作，确认是保护不是故障 |

**怎么停**：随时 `Stop(axis, Immediate)` 或物理急停。

> 自动化版本：`MotionContractTests` 里的「点动方向_正速度必须向正方向运动」就是这条，
> 标了 `[NeedsRealHardware]`。跑它之前一样要先做好上面的安全准备。

## L3 · 单轴定位（**单位，1000 倍**）

**做什么**：`MoveAbs(axis, 10.0mm)`，走完读位置。

| 现象 | 结论 | 处理 |
|---|---|---|
| 实际走 10mm | ✅ 脉冲当量对 | 记下来 |
| **实际走 10m / 10µm** | 脉冲当量错 1000 倍 | 雷赛**脉冲卡**：检查 `dmc_get_position` 是不是被当成了 `_unit` 版；**雷赛总线卡/独立控制器（DMC-E / EMC）：当量是控制器侧的**（`dmc_set_equiv` 设 100 → 控制器发 100 位置 = 1mm，**速度单位随之变 mm/s**）→ 这时**不该**在软件侧再换算；正运动：检查 UNITS 是不是漏推 |
| 指令位置对、反馈位置差 1000 倍 | 两个口径混用 | 检查反馈位置读的是编码器（`GetMpos` / `dmc_get_encoder`）不是指令位置 |
| 反馈位置 == 指令位置（误差恒为 0） | 先看 `HasRealFeedback`：该轴本就无真反馈 → 正常；有真反馈却恒等 → **反馈是假数据** | 无真反馈：别动代码。开环轴（脉冲轴）上这是物理常态；有真反馈：适配器把 `GetFeedbackMm` 写成了返回指令位置，必须修，否则伺服整定和飞拍补偿全无依据 |

> 自动化版本：契约测试的「指令位置与反馈位置_单位一致」+「跟随误差必须非零_抓假反馈」。

## L4 · 停止语义（**急停会不会变减速停**）

**做什么**：以 50 mm/s 运动中，分别发 `Stop(Decelerate)` 和 `Stop(Immediate)`，看停的方式。

| 现象 | 结论 |
|---|---|
| 立即停是**立刻断电式**停止 | ✅ 编码对（雷赛 1 / 正运动 3） |
| 立即停是**慢慢减速** | ⚠ 停止方式编码错了 —— 急停变缓停，撞机风险 |

**怎么停**：物理急停。

## L5 · 回零

**做什么**：`Home(axis)`，看它往哪个方向走、找到什么信号停。

- 雷赛：**回零方向必须显式配置**（`HomeDirection`）—— 默认是「未配置」，回零会**直接抛异常**。
  方向没有安全默认值（负向/正向取决于机构，原点开关在哪侧只有现场知道），猜错 = 朝机构外跑。
  顺序：先按 L2 低速点动确认原点开关在哪一侧，再填 `Positive` / `Negative`。
  另外 `HomeMode` 选 **4 / 8（只记 EZ）** 前，务必确认轴上**真的接了 Z 相** —— 没接时轴会一直跑到撞限位
  （官方停止原因码 24「没有找到 EZ 信号」/ 204 就是这个场景）。
  回零速度走通用速度曲线 `dmc_set_profile`（低速=起始速度、高速=最大速度）—— 代码已按官方路径下发。
  `EzCount` 是**保留参数，固定 0**，不要去改它。
- 正运动：必须先设 `DatumIn`（原点输入口），否则代码会**直接抛异常**而不是让它朝不存在的信号跑。
- **正运动：回零后 MPOS 不一定清零。** 标准回零模式一般会清，但 **ATYPE=4（接入编码器）的轴不保证清 MPOS**
  —— 这时回零后的「工件坐标」是错的。处理：配置 `ClearPositionAfterHome`（走「模式+100」，仅 4 系列支持），
  或在回零完成、位置稳定后调 `ClearFeedbackPosition(axis)` 手动清。**回零后务必对一下位置读数。**
- 第一次回零**必须有人盯着急停**。

## L6 · 插补 / 飞拍（最后做）

| 能力 | 前置 | 必须确认 |
|---|---|---|
| 直线插补 | 单轴全通过 | 正运动走 4 参轴列表式；雷赛需要坐标系号 |
| 硬件比较输出（CMP/PSO） | 通道号已按手册配好 | 触发点位置对不对 —— 用**示波器看输出口**，别信软件读数。<br>雷赛：**`cmp_logic` = 输出有效电平（0 低 / 1 高）**，`time` 是脉冲宽度(us) 且**只有比较模式 4/5 有效**（我们用模式 1，固定传 0）。<br>正运动：模式1 的比较基准是 **带编码器比 MPOS、无编码器比 DPOS**；`opnum` 必须是能做硬件比较输出的口 |
| 位置锁存（LTC） | 锁存源/通道已配好 | 雷赛：**锁存通道由轴号决定，不是靠参数选通道** —— `dmc_set_latch_mode` 的 `triger_chunnel` 是**保留参数固定 0**；**LTC0 锁 0~3 号轴、LTC1 锁 4~7 号轴**（ACC-X400 上 LTC0 = IN14、LTC1 = IN15）。**不是 IN4~IN7**。<br>正运动：总线轴用 R0/R1/Z 脉冲锁存，**脉冲轴用 R2/R3**（imode 18~21 未公开，需显式设 `RegistMode`） |

> 飞拍触发点差一个跟随误差，在 500 mm/s、2 ms 滞后下就是 1 mm —— 每片照片都偏。
> 正运动 `HwPswitch2` 模式1 我给另外 3 个比较点填了 1e9（不可达）占位，**这个填法手册未明写，第一次飞拍必须用示波器确认**。

## L7 · 电子凸轮（**最后做**，三家语义不能平移）

**前置**：L1~L6 全过；L0 已跑通；`cam caps` 已确认你这台卡属于哪种凸轮语义。

**做什么**：把 L0 算出来的结论拿到真机上兑现 ——
离线只能证明「理论上不超限」，**「实际上不抖、不咔哒、跟随误差不报警」必须在机台上看**。

### 7.2 上机顺序（先单轴 → 主从；先空载 → 带负载；先最慢的段 → 全段）

1. **单轴、低速、不带负载**：主轴单轴点转，从轴先脱开或禁用 —— 只确认凸轮表**能被控制器接受**（格式、点数、回读一致），不碰联动。
2. **主从联动、限速**：限速判据用工具定，不用拍脑袋 ——
   **在准备使用的转速下重跑 `cam check`，最大段间阶跃占比必须 ≤ 5%（`velocity_step_warn_ratio`）**；算出来是高危就先拆段或降速，别硬上。
3. **从最慢的段开始**：先用曲线上**斜率最小的那一段**跑通（确认从轴方向、行程、相位），再一段一段加；**每加一段就在接缝位置听一次、采一次波形**（见 7.3）。
4. **空载全段通过后**，再挂实际负载（工装 / 工件）重复第 3 步。
5. **最后才提速**，提速后**必须用新转速重跑一遍 `cam check`** ——
   阶跃速度与主轴速度成正比（`Δv = Δk·θ̇`），提速会把原来合格的接缝变成高危。

### 7.3 段接缝速度阶跃：现场怎么确认（**三者对得上才算数**）

| 观察项 | 怎么测 | 合格判据 | 不合格先查什么 |
|---|---|---|---|
| **伺服跟随误差** | 采从轴跟随误差曲线（指令位置 − 反馈位置），看**接缝的主轴位置**处有没有尖峰 | 接缝处跟随误差峰值 **≤ 从轴位置容差**（容差用工艺给的位置公差；没给就现场定一个并写进配置单）| 尖峰位置与 `cam check` 算出的接缝**对不上** → 先查主轴是不是在凸轮生效区间内做了加减速（CAM-08）、再查单位口径（L3 脉冲当量），**先别改凸轮表** |
| **转矩尖峰** | 看伺服驱动器的**转矩监控曲线**（不要信软件读数）| 接缝处转矩峰值 **≤ 电机 / 驱动器额定转矩**（额定值以现场铭牌与驱动器参数为准 —— **本清单不写死百分比，各家驱动器的过载与报警阈值不同**）| 阶跃占比合格但转矩超 → 查惯量比、加减速段与负载；阶跃占比也不合格 → 就是凸轮表的事 |
| **异响** | 人在机台旁听：接缝经过时有没有单次冲击声（「咔哒」）| 连续跑 **10 次循环无异响**；有异响时**时刻必须落在接缝上**（录音或录像对时）| 异响与接缝对不上 → 查机械：紧固件、联轴器、干涉、润滑，**不是凸轮表** |

> **三者对得上才算数**：`cam check` 算出的接缝位置 ①、跟随误差尖峰位置 ②、转矩尖峰位置 ③、异响时刻 ④ ——
> **四个必须落在同一处**。只有「咔哒」声没有波形证据 = 还没验完；只有波形尖峰没有异响 = 可能只是正常换向。
> 反过来：**②③ 一致但都不在接缝上** → 这是主从相位没对齐，或主轴在加减速（CAM-08），**别去改凸轮表**。

### 7.4 过渡段宽度够不够（**不是只查表**）

- **离线口径**：`cam check` 报告里每个接缝的「过渡段最小主轴宽度」= **阶跃速度 ÷ 从轴加速度上限**
  （代码里的 `min_master_width`）。它给的是**主轴行程**，不是时间。
  ⚠ 用的是**从轴**加速度上限（`--slave-a-max`），填成主轴的就全错。
- **现场三步验**：
  1. **量实际宽度**：接缝附近主轴实际走过的过渡段行程（用主轴位置读数量），
     与报告给的值比 —— **实际 < 计算值 → 过渡段不够**，从轴加速度必然突破上限。
  2. **加宽再算**：把该接缝的过渡段加宽到 ≥ 计算值的 1 倍，重跑 `cam check` ——
     **该接缝的阶跃占比必须 ≤ 5%（`velocity_step_warn_ratio`）**；再上机跑一次，跟随误差尖峰与转矩尖峰应**同步下降**。
  3. **降速再看**：同一张表主轴速度减半 → 阶跃速度减半 → 尖峰应**接近线性地**变小。
     **若减速一半尖峰几乎不变 → 阶跃不是主因**，去查机械与跟随误差口径。
- **典型现象**：过渡段不够 → 从轴加速度在那一瞬间突破上限 → 机械冲击 → 咔哒声 + 跟随误差报警。
  **只看凸轮表看不出来** —— 表上每段都是「合法」的直线，问题出在**接缝处斜率突变**。

### 7.5 这一节也验不了的（**待厂商确认 / 未验证**，不许当成已通过）

- **厂商侧**（只能厂商给，已列入 `docs/厂商手册索取清单.md`）：凸轮表**最大点数**、**凸轮表号数量**、
  `SrcMode` 各取值含义、挺杆（tappet）规则、多段过渡的官方推荐做法、凸轮表是否掉电保持 ——
  官方 C# 绑定只给签名，**DMC3000 手册没有凸轮函数章节** → **待厂商确认**。
- **现场侧**：主从同步精度指标、多个从轴跟同一张表的同步误差、凸轮与插补能否同时启用 ——
  **未验证**（本清单不覆盖）。
- **工具不背的**：安全相关的过冲 / 冲击限值 —— 各家驱动器与工艺的限值不同，**工具不给建议值**。

## 一页纸速查：症状 → 先查什么

| 症状 | 最可能的原因 |
|---|---|
| 指令正常返回，电机不动 | 轴类型 Atype 不对 / 未使能 / 软限位已触发 |
| 走 1000 倍或 1/1000 | 脉冲当量（UNITS）口径 |
| 位置显示与实际差一个倍数 | 反馈位置读成了指令位置 |
| 跟随误差恒为 0 | 该轴本就无真反馈（开环轴 / 脉冲轴）→ 看 `HasRealFeedback`；**声称有真反馈**才是假数据 |
| 停止原因不是 0 | **只有 0 是正常停止**（官方手册 8.7）；用 `GetStopReasonText(axis)` 看人话：限位/急停/ALM/回零没找到信号，各有各的码 |
| 回零报「方向未配置」 | 雷赛 `HomeDirection` 默认不配置 —— 这是保护不是 bug，先点动确认方向再填 |
| 回零一直跑不停 | 雷赛 mode 选成了只记 EZ（4/8）但轴上没接 Z 相 |
| 点动方向反 | 方向编码（0/1 或 −1/1） |
| 急停变缓停 | 停止方式编码 |
| 限位不动作 | IO 位号映射 / 输入极性 |
| 回零后位置差一个固定值 | 正运动 ATYPE=4 的 MPOS 没清零 → 调 `ClearFeedbackPosition` |
| 锁存不触发 | 雷赛：触发口与轴号的对应不对（**LTC0 锁 0~3 轴、LTC1 锁 4~7 轴**；ACC-X400 上是 IN14/IN15，不是 IN4~IN7）；正运动 imode 选错（总线轴 R0/R1，脉冲轴 R2/R3） |
| 飞拍每片位置漂 | 比较点来源（指令位置 vs 反馈位置）/ 通道映射 |
| 凸轮一跑就「咔哒」 | 段接缝速度阶跃 —— 先 `cam check` 看出最差接缝在哪，再确认跟随误差尖峰位置对不对得上 |
| 凸轮一跑伺服就报跟随误差 | 同上；再查 `--slave-v-max` 是不是给大了（严重度按「阶跃速度 ÷ **从轴速度上限**」判，不是 ÷ 峰值速度）|
| 凸轮走完位置不对 | 凸轮表坐标单位（主轴是脉冲 / 角度 / 长度？）+ 从轴行程（CAM-05）|
| 凸轮表一下发就报错 | 雷赛凸轮错误码 2600~2614：凸轮轴未使能 / 数据个数超范围 / 数据表已满 / 表号超范围 / 挺杆编号超范围 |
| 凸轮一动从轴时序整体偏移 | 主轴在凸轮生效区间内做了加减速（CAM-08）—— 主轴要先进匀速段再使能凸轮 |
| 换了卡，凸轮表现完全不同 | 三家语义不能平移：雷赛能整表下发 / 正运动表在控制器侧只能引用区间 / 固高没有凸轮表 |
| DllNotFound / EntryPointNotFound | DLL 位数与固件版本 / 函数名不属于该卡型 |
| 程序一开就崩 | `LTDMC.dll` / `zauxdll.dll` 缺依赖或位数不符 |
