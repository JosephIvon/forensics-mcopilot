## 1. 来源诚实声明（重要）

**本文件的知识来源是《Snap7 Reference Manual》（Davide Nardella，Rev. 8，2016-12-03，对应 Snap7 1.4.2）——这是一份第三方（社区）逆向工程文档与库 API 参考，不是西门子官方 S7 协议规范。** 西门子未公开 S7 协议内部规范，手册原文（p18）亦明确说明：

> "Siemens provides a lot of FB/FC (PLC side), Simatic NET software (PC side) and a huge excellent documentation about their use, but no internal protocol specifications."

因此：s7.json 中每一条值均为该手册的机械提取（含逐字引文 + PDF 物理页码），手册未给出的内容**不做虚构**，原以 `provenance: "judgment"` + `needs: "manual_check"` 标注。**2026-10-21 起引入第二 truth source——Snap7 开源 C++ 源码（1.4.3，LGPL-3.0）**：原 7 条 judgment 全部被源码证实并升级为 `provenance: "mechanical-evidence"` + `evidence_source: "snap7_source"`（`needs: manual_check` 移除，保留原 spec_ref，追加 src_ref{file,line,quote}）；另新增 13 条线缆级源码条目。如需官方/权威校验，仍应对照西门子官方文档（如《System Software for S7-300/400 System and Standard Functions》§33）。

## 3. 提取方法

1. 手册为图片少的 API 参考，文本按页提取后逐词断行严重（如 `201 6`、`signifi cant`）。引文按**"允许行折断点合并"**规则复原（同 modbus.json 惯例），未改动词句、保留原拼写错误（如 `suppled`、`stare`、`suppilied`，在 meaning_zh 中注明 [sic] 性质）。
2. 表格/列表型引文（PDF 表格行被打散）以 **quote 片段数组**给出：每个片段逐字、取自同一页、按原文顺序排列；entry 上以 `table_merge`/`list_merge` 提示。
3. 全量机器校验：`verify_quotes.py` 将每条 quote（去空白后）在提取文本中做包含匹配，**224/224 片段全部命中**（2026-10-21 运行，源码取证后复跑仍 224/224）。
4. 手册为 API 参考手册：functions 各条目的 request/response 字段表是 **Snap7 API 参数层**（函数入参/出参），非线缆字节布局——该缺口已由源码取证闭合（见 §8、s7.json `pdu_wire_*`/`conn_wire_*` 条目）。
5. 源码引文规则（2026-10-21）：`src_ref.quote` 为引用行段（1-based，含端点）**全部非空行的逐字内容**，`\n` 连接、行首缩进裁剪；`line` 为行号/行段。由脚本从源码行段直接生成（非手抄），并经"quote == 源码行段逐行比对"机器校验 **78/78 通过**。

### 8.3 覆盖对照（两大洞的闭合）

**洞 1：TPKT/COTP 建连序列**（原 judgment #1）——源码给出的完整线缆序列：

1. `SckConnect()`：先 ICMP ping（`Ping(RemoteSin)`，PingTimeout=0 跳过）→ TCP `connect()` 到 RemotePort=102（snap_msgsock.cpp L423-448、s7_isotcp.cpp L31）。
2. 客户端发 **COTP CR（0xE0）**：TPKT(4){03 00 lenHI lenLO} + COTP{HLength=0x11, 0xE0, DstRef=0x0000, SrcRef=0x0100, CO_R=0x00} + 参数 11B{C1 02 SrcTSAP-HI LO, C2 02 DstTSAP-HI LO, C0 01 0A}（s7_isotcp.cpp L113-145；帧长 22 字节）。
3. PLC 回 **COTP CC（0xD0）**：服务器把收到的 CR 帧改 PDUType=0xD0、交换 SrcRef/DstRef 回发（s7_isotcp.cpp L160-173、s7_server.cpp L61-66）；客户端收 4 字节 TPKT 后按长度收余量并 `CheckPDU(…, pdu_type_CC)`（s7_isotcp.cpp L205-223）。
4. **S7 层 PDU 协商（0xF0 00）**：`NegotiatePDULength()` 发 S7 头{32 01 00 00 seq 00 08 00 00} + 参数{F0 00 01 00 01 00 01 E0}（并行作业 1/1，PDU 请求 480=0x01E0）；应答头{32 03 … + Error} + {F0 00 01 00 01 00 协商后 PDU}（s7_peer.cpp L74-99）。
5. 之后所有数据走 **COTP DT（0xF0）**：HLength=3、EoT_Num=0x80（s7_isotcp.cpp L267-269）。

**洞 2：读/写 PDU 线缆布局**（原 judgment #2）——源码给出的帧结构：

- **S7 头**：请求 10B `{P=0x32, PDUType(ROSCTR)=0x01, AB_EX=0x0000, Sequence(自增), ParLen, DataLen}`；应答 12B 追加 `Error`（s7_types.h L279-302）。
- **读（0x04）**：ParLen=14（FunRead+ItemsCount+1×12B 项）；项=`{12 0A 10, TransportSize=S7WL*, Length=元素数, DBNumber, Area, Address[3]}`；Address=Start*8（Bit/CT/TM 除外）3 字节大端（s7_micro_client.cpp L101-130）。应答数据项=`{ReturnCode, TransportSize, DataLength, Data}`，0xFF=成功，DataLength 按 TS_Res* 决定字节/bit 单位（L138-150）。
- **写（0x05）**：DataLen=数据长+4；数据项头=`{00, TS_Res*, DataLength}`，TS_Res 映射 Bit→03/Int→05/Real→07/Char→09/默认→04，DataLength 按单位填 Size 或 Size*8；应答为 FunWrite+ItemCount+每项 1 字节返回码（0xFF=成功）（s7_micro_client.cpp L191-296）。
