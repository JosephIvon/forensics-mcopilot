# 项目级教训（mcopilot）
- 2026-10-20：C# 模板里**多行 XML 文档注释的每一行都要带 `/// ` 前缀**。漏掉前缀的行会被当成普通代码，Roslyn 报 CS1519/CS1002 之类的看不懂的错 —— 而且是生成器产物的错，要回 knowledge/sdks/*.json 里修。
- 2026-10-20：P/Invoke 的「读出数据」参数用 `IntPtr` 指针 + C# 侧 `byte[]` 缓冲区，**不要用 `ref int`**。CiA402 对象宽度不统一（0x6040/0x6041 是 2 字节，0x6064/0x60F4 是 4 字节），用固定宽度的 ref 参数等于把「猜错宽度」的风险写进签名。缓冲区长度交给调用方按对象宽度给。
- 2026-10-20：厂商语义未定时**不要提供公开的写封装**。总线轴的使能归属没定死之前，只声明 SDO 写入口（DllImport 保留），不暴露 WriteBusObject 之类的公开方法 —— 公开写封装 = 别人能绕过 Enable() 直接往驱动器写控制字。
- 2026-10-20：**拿到官方 SDK 绑定/头文件后，先把每条 P/Invoke 与官方清单逐行对（函数名/DLL名/参数个数/类型），再谈业务逻辑。** 本轮就靠这一条抓到两个「真机即崩」：正运动的 `ZAux_Direct_SetAxisParam` 与雷赛的 `dmc_set_home_profile` **在官方 API 里根本不存在**（分别导致建连即崩、回零即崩）。声明一个不存在的函数比缺实现更危险 —— 它不报错，只在真机上炸。
- 2026-10-20：**官方绑定的 DLL 名要以官方 C# 绑定为准，不要凭印象**：正运动 `ZAux_*` 全在 **zauxdll.dll**（`zmotion.dll` 是低层 `ZMC_*` 库），雷赛官方绑定全在 **LTDMC.dll**。
- 2026-10-20：正运动的轴参数是**一参一函数**（SetUnits/SetSpeed/SetAccel/SetDecel/SetSramp/SetCreep/SetJerk），**没有通用的 SetAxisParam(name,value)**；AXISSTATUS 用 `GetAxisStatus`，停止原因用 `GetAxisStopReason`（out 是 int*）。
- 2026-10-20：雷赛回零速度走通用曲线 `dmc_set_profile`（vel_mode 0=用起始速度 1=用最大速度），**没有 `dmc_set_home_profile`**；`ez_count` 是保留参数固定 0；停止原因**只有 0 是正常停止**（函数错误码与停止原因是两套码，要分开翻译）。
- 2026-10-20：把官方 C# 绑定导出成 CSV 存进仓库（`knowledge/sdks/official_api/*.csv`），**回归测试拿它当外部真值**逐条校验函数名/DLL名/参数个数 —— 这是「每条结论可核对有据」在代码层的落地方式，比任何自写样例都硬。
- 2026-10-20：**产品形态（插卡 / 独立整机 / 软主站）决定驱动模型，接新品牌先问形态再定路线。** 插卡 = 板卡驱动 P/Invoke（雷赛 LTDMC.dll、固高 gts.dll）；独立整机 = **没有卡驱动可 P/Invoke**，主机侧走通信库（ACS SA/SA-LT 走 ACSPL+ 命令 + SPiiPlus .NET，TCP/IP 或串口）—— 照「绑定 DLL 导出符号」建出来的适配器对独立整机根本连不上。形态已落进 `cards.json` 的 `form_factor`/`driver_model` 字段与能力矩阵第一行。
- 2026-10-20：**「函数前缀不同」≠「库不同」。** 官方 LTDMC 绑定里 `dmc_*` 1252 个 + `nmc_*` 214 个**同在 LTDMC.dll**，`emc_*` 0 个 → DMC-E（EtherCAT 总线版插卡）与 DMC 是同一套头文件（SHA256 相同）、同一个 DLL；**雷赛内部按「卡 / 控制器」分栏，卡 = DMC+DMC-E，整机 = EMC/MC/PAC**。判据只能来自官方绑定的 DllImport，不能来自前缀名。
- 2026-10-20：**型号形态能靠官方手册标题与章节定性，不用猜**：雷赛《EtherCAT 总线卡 用户使用手册》第4章「硬件及驱动程序的安装」→ 插卡；《EMC 系列总线型独立式控制器 用户使用手册》→ 整机；固高《GTS 运动控制器编程手册》原文「工控机插入多张控制卡…靠近 CPU 的 PCI 插槽为 0 号卡」+ 库名 gts.dll → 插卡。手册 PDF 用 pypdf 抽全文 grep 关键词（PCI/PCIe/插卡/板卡/控制器/以太网）比逐页翻快得多。
- 2026-10-20：**「官方 C# 绑定里声明了」不等于「DLL 导得出」** —— 这是第三层真值。本轮实测：`ZAux_Direct_GetNtype` 在官方 `Zmcaux.cs` 与 `zauxdll2.h` 里都有，但随包 **64 位 `zauxdll.dll` 的 PE 导出表里没有**；照抄即 `EntryPointNotFound`。所以 P/Invoke 的校验要做三层：①官方绑定声明 ②官方头文件原型 ③**DLL 导出表（最终权威）**。导表用 struct 直解 PE 导出目录即可（无需 pefile）。另外雷赛 32/64 位 `LTDMC.dll` 的导出集合**不同**（32 位少 8 个函数）→ 位数未定前，保守要求「有几个位数就要在几个位数里都导得出」。
- 2026-10-20：**阈值灵敏度分析必须用二分法定位翻转点，粗网格会骗人**。粗网格（倍数 0.02/0.05/0.1…）会把「当前值离翻转点只有 5~30%」显示成「稳」（实测 `position_tolerance_mm` 真实翻转点 0.014mm，粗网格显示 98% 距离）。做法：网格只圈定区间 → 二分 24 次精确定位 → 再算「相对距离」判脆性。顺带用**静态扫描**核对「配置里的阈值 vs 代码实际读取的阈值」，本轮就抓到 `concurrent_command_ms` 是**死阈值**（配了但代码没读）、`cycle_slow_ratio` 是**硬编码兜底**（代码读但配置里没有）—— 这两条不改，现场标定阈值就是白调，而且调的人不会发现。
- 2026-10-20：**仿真器必须校验端口号**：比较输出/锁存的端口越界在真机上表现为「打到别的端子 → 误触发」或「锁存永不触发 → 误判传感器坏」，都不报错。仿真器不校验就等于默许这类 bug。加了越界抛 `ArgumentOutOfRangeException` 后，仿真器自检从 9 个用例扩到 15 个（新增插补终点/圆弧显式失败/相对定位/回零归零/两个端口越界）。
- 2026-10-20：**厂商手册 PDF 也能当外部真值用**：没有官方 .h/.cs 绑定时，固高手册的「第 13 章 指令详细说明」给逐条原型与语义、「第 14 章 指令索引」给全量指令表（167 条）→ 导出成 `gts_prototypes.csv`（原型+PDF页码）与 `gts_manual_index.csv`（167 条索引），回归测试照样钉住「函数名必须在索引里 / 参数个数必须与原型一致 / **手册里没有的函数不许绑**」。本轮据此确认固高**没有** `SetPulsePerMm`/`GetPulsePerMm`。
- 2026-10-20：**当量变换的公式没给就不要猜方向**：固高当量是 `GT_ProfileScale(axis, alpha, beta)` 的分数比，手册只给取值范围与「|alpha|>|beta|」，**没给公式也没说谁在分子** —— 猜反 = 位置整体偏一个未知比例且**不报错**。做法：不调用当量变换指令，要求控制器保持默认 1:1 当量（手册 p60 原文），脉冲当量由现场提供、软件侧换算，并把「不下发当量变换」写成测试断言。
- 2026-10-20：**厂商没有停止原因码时，要把自己的映射标成「自定义」**：固高只有 32 位轴状态字（0x2 伺服报警 / 0x10 跟随误差越限 / 0x20 正限位 / 0x40 负限位 / 0x80 平滑停止 / 0x100 急停 / 0x200 伺服使能 / 0x400 规划器运动）+ 指令返回值表。适配器按状态字推导停止原因时，**必须在代码注释与知识库里写明「本工具自定义，不是厂商码」**，否则现场会拿别家的码表去对照。
- 2026-10-20：**速度单位可能是 pulse/ms**：固高 `GT_SetVel` 单位是 pulse/ms、`GT_SetTrapPrm` 的 acc/dec 是 pulse/ms² —— 比 pulse/s 小 1000 倍，跨品牌照抄速度数值**不报错**，节拍直接差 1000 倍。换算系数要跟单位一起落进测试（×ppm÷1000、×ppm÷1e6）。
- 2026-10-20：**IO 可能是「类型 + 位图」而不是端口号模型**：固高 `GT_GetDi(diType, &value)` 的 diType 是**类型枚举**（限位/报警/原点/到位/通用各一种），返回值是该类型的位图；通用输入 MC_GPI 的 DI 1~16 ↔ bit0~bit15。雷赛/正运动那边像「逻辑输入口号」的做法**照搬过来就会读错对象**。
- 2026-10-20：**C 结构体里叫「保留」的数组可能带含义**：固高 `THomePrm` 的 `pad1[3]`/`pad2[3]`/`pad3[2]` 里 `pad1[0]`=捕获后回退用哪档速度、`pad2[1]`=启动时是否检测限位/原点 → 手工映射到 C# 字段时必须留出位置（`[StructLayout(LayoutKind.Sequential)]` + 按顺序声明，偏移与 MSVC 一致）。
- 2026-10-20：**「位置锁存」的硬件形态可能完全不同**：固高的锁存 = 编码器捕获（`GT_SetCaptureMode`），捕获源只有 HOME/INDEX/PROBE/HSIO0/HSIO1 —— **普通 DI 根本不能做捕获**。锁存源枚举要按厂商实际能力写，别拿别家的「锁存器 0~3 ↔ IN4~IN7」套过去。
- 2026-10-20：**同一厂商可能有两条产品线，但「前缀不同」依然不能推出「DLL 不同」，「同名头文件」也不能推出「同一个库」** —— 我自己在这个坑上错了两次：①先断言固高 GTS(`GT_`) 与 GEN(`GTN_`)「不共用 DLL」；②查到 GEN 手册例程仍 `#include "gts.h"` 后又改口说「**很可能同一个 gts.dll 同时导出两族**」—— **两次都错**。2026-10-20 拿到官方 SDK 包后实测：`gts.h` 535 条声明、`gts.cs` 473 条声明、4 个 `gts.dll`（各 782 个导出）、MCT2008 那份（569 个导出）**里 `GTN_` 一个都没有** → **GEN 是独立产品线 + 独立 SDK 包**（它例程里的 `gts.h` 只是同名文件）。**判据顺序：①官方头文件/绑定声明 ②DLL 导出表 —— 前缀名、手册标题、同名头文件都不算证据**；雷赛 `nmc_`/`dmc_` 同在 LTDMC.dll 是反例，固高 GEN 是正例。
- 2026-10-20：**厂商清单要按厂商合并，不要按问题拆**：固高 3 条「必须」+ 雷赛 2 条「必须」合并成各家各 1 条（同一个厂商、同一次问齐）→ 「必须」项维持 6 条上限。问得越多越拿不到，合并后反而更快。
- 2026-10-20：**降级绑定的「已核对」和「已确认」要分开写**：固高原型已逐条对过手册 PDF 并记了页码，但官方 `gts.cs` 未到手 → 调用约定与结构体打包**没最终确认**（x86 目标进程调用约定错了就是栈错位）。所以固高这一家**每条都标 `needs-manual-check`**，并在 notes 里写清「拿到 gts.cs 后再改 verified」。（**已于 2026-10-20 解决**：`gts.cs` 到手，34 条全部升为 `official-binding`，见下面几条。）
- 2026-10-20：**厂商自己的两个官方件也会不一致，结构体大小差几个字节就是越界写**：固高官方 `gts.cs` 的 `THomePrm` 是 23 个字段、顺序布局 **88 字节**（`pad1_1/2/3`、`pad2_1/2/3`、`pad3_1/2/3`），官方 `gts.h` 的 C 写法却是 `long pad3[2]`、**80 字节** —— 差 8 字节。适配器回零是「先 `GT_GetHomePrm` 读回再改字段」，**DLL 会把 88 字节写进我们的结构体**，按 80 字节实现就是**内存越界写**（而且不报错，现场表现为随机崩溃）。**缓冲区宁可大不小**：比 DLL 预期大最多被多写几字节，比它小就是越界。做法：把官方 C# 绑定的结构体字段与字节偏移导出成 CSV（`gts_structs.csv`），回归测试逐字段比名称/类型/偏移/总字节 —— 这条测试本轮就钉住了这个 bug。
- 2026-10-20：**手册的数组下标基准与官方绑定的字段名可能不是同一套编号**：手册《编程手册-基本功能 R1.5》p204 写 `pad1[0]`（捕获后到最终位置用哪档速度）、`pad2[1]`（启动回零时是否检测限位/原点），官方 `gts.cs` 把同样的三格叫 `pad1_1/pad1_2/pad1_3` 与 `pad2_1/pad2_2/pad2_3`（**1 基**）→ **手册 pad1[0] = 官方 pad1_1、手册 pad2[1] = 官方 pad2_2**。原先把「检测限位/原点」标志放在第一格 → **启用检测功能静默失效**（不报错，只是没生效）。做法：保留位语义按手册原文逐字抄，注释里写明两套编号的对应关系；**靠名字猜下标是最容易静默错的一种 bug**。
- 2026-10-20：**同一个 SDK 包里可能有多个同名 DLL，拷错不报错但缺功能**：固高 SDK 包里 5 个 `gts.dll` —— 4 个 SDK 的（32/64 位 × 单卡/多卡）**导出表完全相同（各 782 个符号）**，`03_Demo工具_MCT2008/` 那份旧的**只有 569 个、少了 214 个**。做法：PE 导出表真值加「变体」列区分同名不同文件，回归测试只对**依赖的变体**做断言（否则会把「工具目录那份旧 DLL 少导出」误判成绑定有问题），另写一条测试把「MCT2008 那份不是 drop-in 替代品」钉住；notes 里写明**只拷 `02_CSharp封装/<位数>_single_card/` 那份**。
- 2026-10-20：**官方 C# 绑定可能比官方 C 头文件旧**：固高 `gts.h` 535 条声明 vs `gts.cs` 473 条 —— 头文件多 **67 条**新指令（激光控制、智能切割、二维比较、导程螺杆补偿、合并轴、中断、正交/垂直度变换、Move 模式等），绑定另有 5 条头文件没有的（`GT_GantryHoming` 与 4 条速度滤波）。**要接新功能得照头文件补声明，不能照抄绑定**；反过来**只照抄绑定会踩坑**：`GT_GantryHoming` 在官方 `gts.cs` 里声明，但 4 个 DLL 的导出表里都没有它 → 照抄即 `EntryPointNotFound`（正运动 `ZAux_Direct_GetNtype` 同类）。**第三层「DLL 导出表」永远不是冗余。**
- 2026-10-20：**厂商手册里藏着一堆「不用问厂商就能查实」的东西**：固高《GTS-400-PCIe 用户手册 R1.0》第 3 章给了**完整 IO 端子表**（轴信号 CN1~CN4 / 通用 IO 与原点限位 CN9-1·CN9-2 / 辅编 CN12·CN13 / HSIO CN14 / AIN CN19 / 手轮 CN20，逐行抄成 121 行 CSV）、第 6 章给了**电气参数**（脉冲输出上限 **1MHz**、编码器输入 2MHz、通用输入 **9~19V 是不确定区**、通用输出是 **OC 只能拉低**、驱动报警**低电平有效**）、第 1 章给了**型号含义**（主卡 `X=G` 脉冲量输出 / `X=V` 模拟量或脉冲量输出）与**端子板型号**（`GT2-400-ACC2-VB-G/-V`）。**把厂商清单里「能从手册查到」的项划掉，能少问一半**（本轮固高从 3 必须+3 建议 变成只问当量公式/现场型号/GEN 的 SDK）。

## 2026-10-20 雷赛轮（官方手册全过一遍）追加

- 2026-10-20：**厂商手册标「保留参数，固定值为 0」的参数，传非 0 值不是「多传一个参数」，是未定义行为。** 雷赛 `dmc_set_ltc_mode` 的 `ltc_mode`/`filter`、`dmc_set_latch_mode` 的 `triger_chunnel` 全是保留参数（`all_enable` 合法值只有 0 单次/2 连续/3 触发延时急停，1 是保留值）。我们原先把 `ltc_mode` 当「AB 相/锁存信号」、把 `filter` 当「去抖滤波时间(秒)」传了自造值 —— **控制卡不报错，只是行为与预期不同**。做法：保留参数一律传 0，并在绑定 doc 里把「保留参数」原文抄进去。
- 2026-10-20：**配置项对应的是保留参数 = 死配置，必须删。** `LatchFilterS`（锁存去抖滤波时间）在手册里是保留参数 → 配了也不生效，但它在代码里长得像个真配置，现场调了会以为生效。**「配了不生效」比「没这个选项」更坏** —— 后者用户会知道去问厂商，前者用户会一直调。做法：静态扫描「配置项 → 实际读取点」，读不到就是死配置（与 `concurrent_command_ms` 那条同一类）。
- 2026-10-20：**厂商自己标注「内部使用（保留）」的函数不能用** —— 官方 `LTDMC.cs` 把 `dmc_get_sevon_enable` / `dmc_set_sevon_enable` 放在 `//内部使用（保留）` 注释下，返回值语义未公开。我们原先用它判伺服使能（`==0` 为使能）—— 猜错就是**安全信号反了**。改用手册 8.13 明确写了语义的 `dmc_read_sevon_pin`（返回 SEVON 端子电平 0/1，按**轴号**、**每轴一个专用端子**、不占通用输出位），并加 `ServoOnActiveLevel` 配置项（有效电平取决于驱动器接法，不能写死）。**判据：手册里写清语义才用；标「保留」「内部使用」的一律不用。**
