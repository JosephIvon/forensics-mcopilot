## 6.1 概念：归因 = 证据 + 下一步，缺一即降级

诊断类系统最常见的失败形态不是"诊断错了"，是**诊断得没法用**：一句"可能有
问题"，既给不出证据行号，也给不出下一步动作。mcopilot 对"诊断"的验收标准
只有一条（`docs/kb3_判据抽取.md` 落地目标原文）：

> 输出的诊断，达到「可被追问到底」的等级：每条结论带 slug、每条结论带
> ≥2 条证据、每条结论有反证、每个说不清的故障模式都被显式登记为
> 「不可评估」、改进量必须挂在依据层级上。

本章的核心命题：

> **归因不是"说出原因"，是"证据在哪、下一步是什么"二者同时在场。**
> 只有原因没有证据 = 猜；只有证据没有下一步 = 抱怨；说不清 = 显式 UNKNOWN，
> 停下来交人——绝不猜，也绝不在猜的基础上自动行动。

## 6.2 检出引擎：七条规则，只吃结构化特征

`forensics_comm.py`（342 行）消费 comm_log/1 帧级日志，按 7 条封闭 cause 词表
的规则产出检出（`src/mcopilot/agents/forensics_comm.py:19-32`）。七条规则的
触发条件全部是**结构化特征**——error 枚举值、exception_code、tid_expected/
tid_got 对、expected_len/got_len 对——不做自由文本猜测（`src/mcopilot/agents/forensics_comm.py:12-13`）：

| cause | 触发条件（结构化） | 粒度 |
|---|---|---|
| crc_error | error=crc 的 RTU 链路失败条目 | 逐条 |
| timeout | error=timeout 的等待超时条目 | 逐条 |
| conn_reset | error=reset 的连接重置条目 | 逐条 |
| short_read | error=malformed 且 got_len<expected_len | 逐条 |
| malformed_frame | error=malformed 且无短读证据 | 逐条 |
| stale_frame_tid | error=other 且 tid_expected≠tid_got | 逐条 |
| exception_storm | 同流连续 ≥3 条带 exception_code 的 resp | 每段 |

三个设计点值得停下：

- **宁可少报也不误报**（`src/mcopilot/agents/forensics_comm.py:14-16`）：error=refused / no_response、以及
  error=other 而无 TID 证据的条目，一律**不**产出检出。检测器的美德排序
  写死在代码里：漏报可由农场补规则，误报烧掉的是整个告警渠道的信用。
- **风暴阈值不是拍的**（`src/mcopilot/agents/forensics_comm.py:63`）：STORM_MIN=3 由农场 sweep 场景（4 连异常）
  构造性钉住——阈值有场景坐标，不是经验玄学。
- **不带病检出**（`src/mcopilot/agents/forensics_comm.py:16-17`，R2 同款）：输入日志必须先过 comm_log/1 契约门，
  复用 validate_comm_log.py 同一裁判，违规即拒跑——归因层不修数据，修采集端。

## 6.3 失败签名库：六条签名的完整表结构

帧级检出之上是**缺陷级归因**。`failure_signatures.json`（6 签名）是接入闭环
的失败解读语料库，每条都是本轮战役亲手挖出并已修复/门禁化的真实缺陷
（`knowledge/protocols/failure_signatures.json:4`）。先给全表结构——这本身就
是大纲开放题的参考答案：

| 字段 | 装什么 | 实例（SIG-G8-DOC-DRIFT） |
|---|---|---|
| id | 签名身份 | `SIG-G8-DOC-DRIFT` |
| signature | 失败证据文本上的正则 | `docsync-fail\|!= 实算` |
| root_cause | 根因叙述（含"不是什么"） | 文档抄旧结论，不是代码错 |
| next_action | 确定性下一步 | 按行把文档改回实算值，禁止反向凑 |
| action_class | 动作类别（封闭词表） | escalate |
| gate | 关联门禁 | G8 |
| evidence | 可查证据锚点（path#锚 / commit） | gate_negative.ps1#N4 等 3 条 |
| probe_sample | 命中样例（真实原文） | `[docsync-fail] README 黄金测试数 31 != 实算 30` |

六条签名一览（`knowledge/protocols/failure_signatures.json:11-99`）：

| id | 抓什么 | action_class | gate |
|---|---|---|---|
| SIG-01-OLD-DLL-CS1061 | 旧产物 DLL 构建链漂移 | rerun_canonical | G1/G3 |
| SIG-P1-1-BITBYTE-CAP-245 | 位响应上限回归 245 | rerun_canonical | G2/G3 |
| SIG-P1-2-SHORT-READ | 从站短读（劣化/丢数据） | rerun | G3 |
| SIG-P1-3-POISONED-CONN | 管道被残帧污染 | rerun | G3 |
| SIG-RTU-CRC-REJECT | 串行链路 CRC 失配 | rerun | G2/G4 |
| SIG-G8-DOC-DRIFT | 文档数字漂移 | escalate | G8 |

四个语料库级设计，每条都在防一种腐烂：

- **匹配纪律**（`knowledge/protocols/failure_signatures.json:5`）：按 signatures 数组顺序逐条 re.search，首个命中即归因；
  全部不命中 → 结构化上报 UNKNOWN——"绝不猜、绝不无签名重试"。
- **动作词表封闭**（`knowledge/protocols/failure_signatures.json:6-10`）：只有 rerun（有界重试）/ rerun_canonical（弃用
  漂移副本恢复模板源）/ escalate（停下交人/LLM）三类。归因 ≠ 自动修复：
  除两个确定性动作外一律停。
- **must_not_match_samples**（`knowledge/protocols/failure_signatures.json:100-106`）：5 条**不许命中**的样例——PASS 行、
  正常编译行、自相矛盾的测试输出……这是签名库自己的负向测试，防"正则太宽
  抓良民"（与第3章负向测试同律，作用对象换成了匹配器本身）。
- **诚实边界三条**（`knowledge/protocols/failure_signatures.json:107-111`）：只收亲手挖出且有可查证据的缺陷，不为凑数
  编造；evidence 可查性由 tests/test_onboard_loop.py 守护；已知签名=确定性
  归因，归因≠自动修复。

## 6.4 接入闭环：智能体在外，确定性内核在内

`onboard_loop.py`（613 行）把检出与签名库缝成自动闭环。架构原则一句话
（`scripts/onboard_loop.py:8`）：**智能体在外、确定性内核在内**——内核只拥有
两类决策权：解读失败（签名确定性匹配）与选择下一步（按 action_class），
全部执行走既有门禁，"不自创测试路径、不绕过任何门"（`scripts/onboard_loop.py:11-12`）。

状态机六步（`scripts/onboard_loop.py:16-28`）：SENSE（查能力矩阵）→ PLAN（起从站+跑契约门）→
EXECUTE（canonical/sandbox 两条既有路线）→ INTERPRET（逐签名匹配，无命中
出 UNKNOWN 证据包）→ DECIDE（rerun/rerun_canonical/escalate/UNKNOWN 停）
→ REPORT（接入报告落盘）。

退出码=接入成败的四种语义（`scripts/onboard_loop.py:30-34`）：

| 码 | 语义 | 后续动作权在谁 |
|---|---|---|
| 0 | 接入成功 | — |
| 20 | UNKNOWN 失败升级（语料库无匹配） | 人/LLM（证据包已落盘） |
| 21 | 已知失败但重试/恢复预算耗尽 | 人（归因报告已落盘） |
| 22 | 环境/用法错误 | 调用者 |

注意 20 的设计：**语料外的失败不是"重试一次试试"，是带着完整证据包升级**。
自动重试对未知失败的全部作用是把随机性涂改成运气——语义上把"没见过"伪装
成"见过了但没修好"。

## 6.5 判卷器：故意简单到无法作弊

归因质量的裁判是 `eval_forensics.py`（162 行）。判定口径（`scripts/eval_forensics.py:13-16`）：

> 检出正确 ⇔ (id, cause) 二元组同时出现在 detections 与 truth（集合语义，
> 重复折叠）。precision = TP/(TP+FP)，recall = TP/(TP+FN)；输出漏检清单与
> 误报清单。

口径注释自评"故意简单到无法作弊"——没有阈值、没有权重、没有可调参数，
调无可调。漏检/误报两张清单随分数输出，任何一方对分数不服，直接查清单对质。
同款纪律：R2 违规拒跑（`scripts/eval_forensics.py:32` 复用 validate_comm_log 同一裁判，归因层不修数据）。

2026-10-22 本机执行，两条退出码均为 0：

```

  selftest 抑制: 干净流+孤例+未知形态 检出 0 条 [OK ]（期望 0）
  selftest 回查: 检出证据行满足规则前提 [OK ]

> python scripts/eval_forensics.py --selftest
  selftest 样例: TP=1 FP=1 FN=1 precision=0.50 recall=0.50 [OK ]（期望 1/1/1，P=R=0.50）
  漏检清单: [('L2', 'timeout_after_req')]
  误报清单: [('L2', 'crc_error')]
eval_forensics --selftest: PASS
```

检出引擎的三段自测各有含义：检出面（7 规则各中 1）、**抑制面**（干净流/孤例/
未知形态检出 0——"宁可少报"是断言不是口号）、回查面（证据行真的满足规则
前提）。判卷器的 0.5/0.5 连同漏检/误报两张清单一起出——**分数与对质材料
同时在场**。

**知识题**

1. §6.3 表结构里 evidence 与 probe_sample 各防什么？删掉 probe_sample 会怎样？
2. 为什么 UNKNOWN（20）不走 rerun？"多试几次"错在哪一层？

**反事实题**（参考答案=真实设计，含代价）

4. 把七条检出规则换成一个小型分类器（输入帧特征，输出 cause 概率），会失去什么？
   *参考*：至少三样——①每条检出失去"满足规则前提"的可回查性（§6.6 回查面
   作废）；②阈值变成可调参数，判卷"无法作弊"的性质作废；③农场三断言的
   "构造==现实"断言失去对照物（规则是显式的，才能对角）。换来的是对未知
   形态的泛化——而战役的诚实边界（`src/mcopilot/agents/forensics_comm.py:38-40`）明确说了：覆盖率要等真实分布，
   不靠分类器脑补。
5. 开放题：给你的领域设计 failure signature 表。*参考思路*：直接抄 §6.3
   八字段——重点是三个容易省掉的：probe_sample（真实原文，防正则写歪）、
   must_not_match 样例（防正则太宽）、action_class 封闭词表（防"自动处理"
   蔓延成任意执行）。宁可先只有一条签名，六件套齐全；不要先攒二十条，
   件件缺证。
