## 2.1 概念：自洽不是有效，可信要分级

工程汇报里最廉价的一句话是"测试全过"。它不假，但它省略了一个问题：
**这些测试有资格裁决这件事吗？** 自己造的样例喂给自己写的规则，全绿只证明
这套东西自洽——自洽是"没有内伤"，不是"对症下药"。

本章的核心命题只有一句：

> **构造真值（Tier A，自洽）≠ 外部真值（Tier B，对打）≠ 部署真值（Tier C，实测）。
> 三者不可互相冒充；够不到的那一级，显式挂起——挂起不是欠账，是设计。**

这条纪律在战役里的出生证明，是共享记忆的第 3 条（2026-10-19，来源：纠正）：

> 声明准确率/检出率前必须绑定可核对的清单或外部真值（如植入缺陷清单、解析解、
> 厂商手册），并在文档里明确区分「自洽性验证」与「外部证据」；禁止把自己造的
> 样例 + 自己写的规则当作有效性证明。（`%USERPROFILE%\self-improving\memory.md:13`）

由此推出三条工程纪律，本章的真实工件将逐条兑现它们：

1. **每份证据标级**——说出"我知道什么"之前，先说清"这是哪一级知道"；
2. **自洽证据永不冒充有效性证明**——Tier A 的满分不兑换 Tier B 的结论；
3. **够不到就显式挂起**——挂起要登记、要对账、要写明卡在什么上，而不是删掉不提。

收尾决策清单把它钉成正式裁决 T2："Tier A 构造真值（自洽）/ Tier B 真实分布
（Lemay 12852 帧 FPR=0、issues 35 分账确认 11/报告 24）/ Tier C 真机（挂起）
——自洽证据永不冒充有效性证明"（`decision-lists/mcopilot-b53ac62.md:30-32`）。

## 2.2 Tier A 构造真值：真值在注入那一刻即知

`scripts/fault_farm.py`（1264 行，零第三方依赖）是 Tier A 的批产车间。它对每个
故障场景执行同一套动作：「注入 → 客户端/探针收发与错误事件落成 comm_log/1 条目
→ 按注入参数构造标签」——文件头一句话点破 Tier A 的本质：**真值在注入那一刻
即知，不依赖事后观测**（`scripts/fault_farm.py:9-10`）。

十场景清单（TCP 路 8 + RTU 路 2，`scripts/fault_farm.py:22-34`）：

| 场景 | 注入 | 预期检出 |
|---|---|---|
| clean | 正常读写 4 事务（FC6 写/FC3 读交替） | 负样本，检出必须为 0 |
| sticky_stale | 每响应附发旧 TID 陈旧帧 | 每事务≥2 检出 stale_frame_tid |
| fragment_byte1 | 响应逐字节滴流 | 时序容忍：检出必须为 0 |
| short_read | 沙盒副本对客户端注入劣化 | 检出 short_read；阳性对照=0 |
| timeout | 连接后从站停答 | 检出 timeout |
| conn_reset | SO_LINGER(1,0) 中途断连 | 检出 conn_reset |
| malformed_reply | 回协议标识≠0 的垃圾帧 | 检出 malformed_frame |
| exception_sweep | 逐请求回异常码 01.. | 检出 exception_storm |
| crc_corrupt / rtu_timeout（RTU 路） | 首响应坏 CRC / no-respond 桩 | 检出 crc_error / timeout |

构造性真值三断言，每场景自动执行、任一不满足即该场景 FAIL
（`scripts/fault_farm.py:36-42`）：①注入生效（从站标记或探针观测到注入特征）；
②构造==现实（真值行指向的日志条目必须携带该 cause 的结构化签名）；③日志合法
（过 validate_comm_log 全量校验——"绝不带病出农场"）。

然后是本章最重要的一段代码注释，农场自己的诚实边界
（`scripts/fault_farm.py:48-50`）：

> 本农场的真值全部是注入参数的构造性推论——它证明「批产→检出→判卷」管线的
> 机制正确（构造类 100% 检出、clean 零误报），**不证明现场故障分布**；分布校准
> 属 Phase 2（真实语料）与 Phase 3（真机波次）。

"构造类 100% 检出"六个字，证明力到机制为止——Tier A 的满分只兑换 Tier A 的
结论，纪律 2 不是口号，是写进工具文件头的自我声明。连合并日志的行号 L\<n\> 都
被定为"判卷与检出的统一坐标"（`scripts/fault_farm.py:15`）：自洽证据的每一行，
也要装上门牌号。

## 2.3 Tier B 外部真值：锚点库与真实语料

Tier B 的意思是"跟外部世界对打"。战役里它有两种形态。

**形态一：外部真值锚点库。** `knowledge/protocols/anchors.json`（171 行）登记
**16 个锚点**（本仓锚点实数），自述职责："门禁 scripts/gate_anchors.py 重算比对，
防一手件/提取文本/源码包被静默篡改"（`anchors.json:4`）。按 role 分账（程序化
复核：spec_pdf=7、source_snapshot=1、tool_installer=4、extracted_text=3、vendor_csharp_binding=1）：

| role | 数 | 例 |
|---|---|---|
| spec_pdf | 7 | Modbus AP V1.1b3 官方 PDF：932519 字节 + sha256（`anchors.json:9-14`） |
| source_snapshot | 1 | Snap7 1.4.3 源码包（S7 错误码取证的一手件）（`knowledge/protocols/anchors.json:68-75`） |
| tool_installer | 4 | com0com 虚拟串口安装包（RTU 行为契约的依赖件）（`knowledge/protocols/anchors.json:76-107`） |
| extracted_text | 3 | 规范提取文本（quote 反查的同源弹药）（`knowledge/protocols/anchors.json:108-134`） |
| vendor_csharp_binding | 1 | 雷赛官方 C# 托管绑定 `LTDMC.cs`（806 条声明）——本仓 P/Invoke 返回类型的雷赛侧来源（`anchors.json:146-155`） |

三个设计点值得停下：

- **连提取文本和安装包都钉哈希**。quote 反查对的是提取文本，文本被篡改则反查
  全盘失真——锚点带 `reextract_from/reextract_tool/reextract_check` 三件套，
  门禁可重跑提取链，要求"哈希必须与在档 txt 完全一致"（`anchors.json:115-117`）。
- **外部真值也有成色，锚点库不粉饰**。FOCAS 手册如实标注"第三方分发的 FANUC
  手册副本；官方 B-63xx 未获得"（`anchors.json:41`）；Snap7 参考手册标注"第三方
  逆向工程文档——S7 无官方公开协议规范"（`anchors.json:61`）。
- **外部性带来的不确定性用显式开关表达**。URL 存活检查"默认 WARN 不计入失败
  （CI 无网不误报）；--strict 时计入失败"（`anchors.json:157-163`）——不用静默。

**形态二：真实语料。** `knowledge/protocols/real_corpora/` 恰好 2 个文件（当日
实列）：`issues_corpus.jsonl`（39578 字节）与 `sources.md`（9054 字节）。分账
原文：**"共 35 条；confirmed 11 / reported 24；覆盖 7 个仓库"**
（`real_corpora/sources.md:6`）——本书当日程序化复核该 JSONL：35 行、11/24、
7 仓库，逐项一致。两档纪律（`real_corpora/sources.md:5`）：confirmed 须有维护者
回复或修复 commit 佐证，reported 只是用户报告；"宁缺毋滥未收"（`knowledge/protocols/real_corpora/sources.md:64-65`）。

真实分布的另一场对打，是 Lemay 真机测试床语料的首测
（`docs/项目回顾与收尾_20261021.md:384-385`）：

> natural_polling_only 全量：58325 包 → 12852 Modbus 帧（FC1/2/3 各 4284，纯读），
> 标签全 0，forensics_comm 检出 0 条 → 真实分布误报率 = 0/12852 = 0.000000。

克制体现在紧随其后的那句："首测无基线，此数字只报告不设阈值；它的意义是「对
1.3 万帧真实正常流量，现有 7 规则无一误发」——**不是「误报率就是 0」**"
（`docs/项目回顾与收尾_20261021.md:387-389`；门禁同口径："真实分布误报率只报告
不设阈值"，`scripts/gate_corpus.ps1:16`）。攻击段同样诚实定性：characterization
探测段 6689 帧、检出 37 段 exception_storm、窗口覆盖率 0.4977，是"正对照"——
攻击在 Modbus 面可见时引擎确实开火（`docs/项目回顾与收尾_20261021.md:399`）；
三段主机层攻击在 Modbus 面 0 帧，如实报 n/a，不硬凑规则（`scripts/fault_farm.py:395-404`）。这本账
在第 5 章展开。

## 2.4 Tier C 部署真值：显式挂起即设计

够到 Tier A、Tier B，不等于够到 Tier C。真机互操作这一级，战役停在停机点时
就是没做——但"没做"被做成了设计。`docs/TODO需实测_协议域.md`（18 行）登记
全部 5 条显式挂起（`docs/TODO需实测_协议域.md:9-13`）：

| # | 挂起项 | 卡在什么上 |
|---|---|---|
| T1 | diagslave 正式模拟器对跑同一契约套件 | 当前对端=自建契约桩，非第三方实现 |
| T2 | 断线重连语义 | 桩不可模拟半开连接 |
| T3 | 广播（unit=0）行为 | 串行域语义，TCP 桩不可模拟 |
| T4 | SLMP 位单位读写 + 真机 CPU 互操作 | 桩本轮只实现字单位 |
| T5 | SLMP 副头部真机核对 + 结束代码语义表 | 与自建桩互洽但非独立证据 |

注意每条都写明了**卡在什么环境事实上**——挂起的本质是"知道自己在等什么"。
支撑这套挂起的是一条对账纪律：所有 `TODO[需实测]` 注释必须在本文件登记
（编号 + 状态），`tests/test_protocol_modbus.py::test_TODO需实测追踪对账` 双向
对账，真机波逐条消除（`docs/TODO需实测_协议域.md:3-5`）——漏登记、已消除未
销账，都会被测试抓红。收尾决策清单对这一结构的裁决原文
（`decision-lists/mcopilot-b53ac62.md:19-20`）：

> **B1 软件层收尾 ≠ 全部完成**：真机验证 T1-T5 显式挂起，Tier C 冻结至硬件到场
> ——这是设计性挂起，不是遗留欠账（对照：`docs/TODO需实测_协议域.md`）。

同文件还登记两处"同属诚实边界"的补充：引文复核三层判定（严格逐字 36 / 签名
同源 17 / judgment 跳过 7），一条概括性引文补标 `needs: manual_check`
（`docs/TODO需实测_协议域.md:16-18`）——挂起制度连"哪句话只是概括"都要管。

## 2.6 战例一：CNC——真值锚点的选择权（作者亲历）

作者亲历，另一场 CNC 域的智能体开发：智能体交来第一版方案，把资产与标准的
优先级排错了。作者否决该方案，并指定两条最重要资产和标准——**机械图纸和
NC 程序**。给出的理由原文是：

> "机械图纸和 NC 程序为最重要两条资产和标准——因为 CNC 编程操机我自己亲自
> 做过 2 年，有这个发言权。"

这一幕值得停在两个层次上：

1. **真值锚点的选择权来自亲手经验。** 2 年编程操机让"哪份文件说谎成本最高"
   成为肌肉记忆——图纸与 NC 程序错了，撞刀、报废，代价落在物理世界；别的
   文档错了，多半只是难看。
2. **选择本身就是经验判断，它没有更低一层的锚点可挂。** 锚点库防"选定的外部
   件被篡改"；但"选哪个外部件"这一步，锚点库帮不了——那是经验在裁决。

与共享记忆第 16 条对照（2026-10-22，来源：纠正）："陌生领域不瞎立基准：用外部
锚点（官方文档/厂商件/解析解）替代个人基准；**熟悉领域才先立个人基准**"
（`%USERPROFILE%\self-improving\memory.md:26`）——CNC 正是熟悉域，个人基准合法
且不可外包。两件事不矛盾：**外部锚点保证锚不被挪动，亲手经验决定锚钉在哪里。**

耐久对照物：本战役 CNC 域的一手件最终以 FOCAS 手册锚点入库，且来源性质如实
标注"官方 B-63xx 未获得"（`knowledge/protocols/anchors.json:41`）——第三方翻印
副本也敢入库，因为成色写在了明面上。

## 2.7 战例二：伺服——非专家背书标"工作假设"（作者亲历）

同一战役的伺服线，镜像的一面。智能体在开发中写下一份前馈污染判据，展开约
