# 第4章 契约先行：让"什么算对"先于生成物存在

> **本章承接**：第 3 章的门禁是通用护栏，第 4 章把它落到业务口径上：先定义「什么算对」，再写生成物。
> **学完你会**：能写出一条业务不变式（I1-I6 式），并当场让校验器拒收一份坏数据（§4.6 动手：现跑契约裁判）。
> **前置**：第 3 章（知道裁判必须先存在）。本章需要 Python 3.9+，无硬件。

> **可验证主张**：见 §4.8 ｜ **讲师切分**：见 §4.8

## 4.1 概念：契约先行不是先写文档，是先立裁判

第3章证明门禁的价值在"能拦"。本章回答下一问：**拦的依据从哪来，什么时候定？**

常见的做法是先产出一批数据，回头补一份规范。补出来的规范有两个先天缺陷：它描述既成
事实，只能迁就生成物，约束不动它；它没有裁判，全靠人读人守——而人守规范守不过三天。

mcopilot 把顺序反过来。现场通信日志契约 `comm_log/1` 落档于 2026-10-21
（`comm_log_contract.json:3`），落档当天的诚实边界写得毫无遮拦：仓库内**零份真实现场
日志、零份标注真值集**，内嵌样例全是合成数据，"只证明格式与工具链可跑，不构成任何
归因能力的证据"（`comm_log_contract.json:125`）。

没有任何一帧真实数据时，先立契约。这不是本末倒置，这是本章核心命题的字面义：

> **契约先行 = 生成物在被写出来之前，"什么算对"已经机器可判。**
> 契约的价值不在"写下来了"，在"有人逐条裁"——裁判唯一、退出码可数、作者无豁免。

权力链在契约头部一句话交代完：`scripts/validate_comm_log.py` 是本契约的**唯一裁判**
（退出码=违规数），归因管线 `eval_forensics.py` 只吃通过该门的日志，"不合规日志一律
先修采集端，不在归因层猜格式"（`comm_log_contract.json:4`）。

三个词值得画线：**唯一裁判**（不存在第二口径）、**退出码=违规数**（违规可数，不是
"感觉有点乱"）、**不猜格式**（宁可拒收，不将就解析）。

## 4.2 契约解剖：134 行 JSON 里的四层结构

（本节行位坐标均指 `knowledge/contracts/comm_log_contract.json`。）

| 层 | 行位 | 裁什么 | 硬数字 |
|---|---|---|---|
| 身份层 | `knowledge/contracts/comm_log_contract.json:2-5` | schema id `comm_log/1` 不符即拒收；纪律承袭 axiscope C1 契约 | 5 条同款纪律 |
| 字段层 | `knowledge/contracts/comm_log_contract.json:15-90` | 11 个字段的类型/必填/枚举/取值域 | 必填 7，封闭词表 3 组 |
| 不变式层 | `knowledge/contracts/comm_log_contract.json:92-99` | 跨字段派生判断 I1-I6 | 6 条 |
| 红线层 | `knowledge/contracts/comm_log_contract.json:105-109` | 裁判自身的权力边界 R1-R3 | 3 条 |

三个设计点值得停下：

- **词表封闭、按域隔离**。channel 只收 `tcp/rtu`（`knowledge/contracts/comm_log_contract.json:31`），direction 只收
  `req/resp/broadcast`（`knowledge/contracts/comm_log_contract.json:36`），error 只收 7 个枚举值（`knowledge/contracts/comm_log_contract.json:71`）——词表外的值不需要
  讨论，直接计违规（校验器实现在 `validate_comm_log.py:108-113`）。scope 同时声明：
  其他协议接入时"另立 schema id，不共用词表"（`knowledge/contracts/comm_log_contract.json:8`）——契约按协议域封闭，不做万能格式。
- **契约声明"不裁什么"**。non_goals 三条：resp/req 配对完整性不在校验范围（`knowledge/contracts/comm_log_contract.json:101`）；
  frame_hex 与字段的深检一致性不裁（`knowledge/contracts/comm_log_contract.json:102`）；采集体量红线暂不设，理由是纪律级的——
  "本轮零份真实日志，红线数字定了也是编的"（`knowledge/contracts/comm_log_contract.json:103`）。**机器判不了的，宁可挂起，
  不编标准**——与第2章"挂起不是欠账是设计"同源。
- **每条裁断都有真值来源**。knowledge_refs 四条把裁决规则回链协议知识库（modbus.json
  的编址/广播/异常响应/异常码条目，`knowledge/contracts/comm_log_contract.json:128-133`）——契约不是凭空立法，是把已锚定的
  外部真值（第2章 16 锚点体系）**编译成机器可判的规则**。unit_id 保留段的判词是
  最好的样本："保留段地址 248-255 出现在日志里即为违规（不是罕见值，是不该发出去的
  帧）"（`knowledge/contracts/comm_log_contract.json:44`）。

## 4.3 大纲习题逐条作答：I1-I6 各拦哪类生成错误

（大纲习题原文：I1-I6 各拦哪类生成错误？以下逐条作答。不变量内容均现场实取自
`comm_log_contract.json:93-98`；实现坐标指 `scripts/validate_comm_log.py`。）

| # | 不变量（契约原文） | 拦哪类生成错误 | 裁判实现 |
|---|---|---|---|
| I1 | 流内单调：同 (channel, device.host_or_port) 的 seq 严格递增，跨流各自独立（`knowledge/contracts/comm_log_contract.json:93`） | **复用/回卷类**：采集器重启后从旧 seq 续写、同一批帧被重复消费、多进程并发写同一流 | `validate_comm_log.py:100-104` |
| I2 | 广播形态：broadcast ⇒ channel=rtu 且 unit_id=0 且无 exception_code 且无 error（`knowledge/contracts/comm_log_contract.json:94`） | **语义形态类**：广播记进 tcp 流、广播带非零地址、给广播配异常码或失败事件——广播后从站不回响应（SL V1.02 §2.4.1），这些帧物理上不存在 | `validate_comm_log.py:142-151` |
| I3 | 异常归属：exception_code∈1..11 ⇒ direction=resp（`knowledge/contracts/comm_log_contract.json:95`） | **方向归属类**：把异常码挂在 req/broadcast 上——异常响应只会从从站回来，等于把"回答"记成"提问" | `validate_comm_log.py:130-131` |
| I4 | 互斥：error 与 exception_code 不得同时出现（`knowledge/contracts/comm_log_contract.json:96`） | **层混叠类**：一行既声明"链路级失败事件"又声明"协议级异常响应"——同一帧不可能既"没收到完整帧"又"从站明确回了异常码" | `validate_comm_log.py:137-138` |
| I5 | other 可归因：error=other ⇒ notes 非空（`knowledge/contracts/comm_log_contract.json:97`） | **黑洞行类**：说不清的失败不留一句说明——契约在字段层已把话挑明："说不清的失败不许进日志"（`knowledge/contracts/comm_log_contract.json:89`） | `validate_comm_log.py:139-140` |
| I6 | 时间合法：timestamp_utc 必须是真实存在的 UTC 时刻（`knowledge/contracts/comm_log_contract.json:98`） | **时间构造类**：2 月 30 日类不存在的时刻；本地时间与时区偏移写法一律不收（`knowledge/contracts/comm_log_contract.json:20`——现场机器时区不可信，归一是采集端的责任） | `validate_comm_log.py:48-56` |

两点观察：

- 六条不变量全是**跨字段**判断：单看每个字段都合法，合起来物理不可能。字段层管
  "每个词合法"，不变式层管"这句话在物理世界里可能发生"。I2 是最典型的四合取——
  校验器把它拆成四条逐条报（`validate_comm_log.py:142-151`），打中的是同一个事实：
  广播无响应。
- 连"两套真值打架听谁的"都提前裁好：seq 与行序冲突时以 seq 为准，"行序错乱本身
  不算违规，seq 乱才算"（`knowledge/contracts/comm_log_contract.json:13`）；序列性按流分流判定，全文件混写多条流合法（`knowledge/contracts/comm_log_contract.json:12`）。
  契约的完备性不在条款多，在**不给现场裁量权留缝**。

## 4.4 大纲习题二作答：不设红线 R1-R3，会发生什么

红线原文（`comm_log_contract.json:106-108`）：

> **R1** schema 不符即拒收：schema 字段缺失或值不为 comm_log/1（契约头部）→ 整文件
> 拒收，不算行级违规算文件级。
> **R2** 不带病归因：validate_comm_log 退出码非 0 的日志集，eval_forensics 必须拒跑
> （先修采集端）。
> **R3** 不静默改数据：校验器只报不修；任何字段规范化（如时间归一）是采集端的责任。

总纲写在 style_ref 里："数据质量红线宁可拒收不可带病放行；采集端缺陷不静默修复"（`knowledge/contracts/comm_log_contract.json:5`）。

**构造场景**（作者亲历口吻的虚构推演，非仓库实录，仅用于说明三条红线各拦一环）：
现场送来 2000 帧日志，采集端脚本带两个 bug——时间戳写成本地时间（+08:00 偏移写法），
schema 字段拼成了 `comm_log/2`。抽掉三条红线，事故会这样走完：

1. 没有 R1：归因层看到不认识的 schema，选择"猜格式继续解析"——正是契约头部明令
   禁止的行为（`knowledge/contracts/comm_log_contract.json:4`）。身份不对的文件获得了行级待遇，错误从第一行就开始累积。
2. 没有 R3：校验器好心顺手把时间归一成 UTC 再放行——采集端的时区 bug 从此被数据层
   掩盖，永远不会再有人去修；而且换台机器跑原始日志，结论根本复现不出来。
3. 没有 R2：带着违规的日志集照样进了 eval_forensics，precision/recall 照样出榜
   （归因评测的产出物，`comm_log_contract.json:121`）——之后每一个引用这组指标的
   结论，脚下都垫着一份没人修过的带病日志。

三条各断一环，结局是没有人知道归因结论建立在"被猜格式+被静默修补+带病放行"的数据上。
**红线的排序也有讲究**：R1 在文件级拒收（身份不对，一行都不看），R2 在管线级拒跑
（行级有病，下游不许吃），R3 约束裁判自身（只报不修，问题留在产生它的层）。

## 4.5 契约是第三方口径：作者自己写的东西也要过契约门

"第三方"不是指作者是别人，是指**判断标准先于判断对象存在，且判断者无权修改标准**。
mcopilot 里这个原则有两个岗位：

**岗位一：协议提取 SOP 的反查门。** 八步管道（`协议提取SOP.md:21-27`）每步带验收门。
铁律一"无裸提取"：每条结论必须带 spec_ref + provenance，引文逐字复制自提取文本，
"反查不过=条目不存在"（`协议提取SOP.md:10-11`）——注意这条的时态：**反查通过之前，
条目不曾存在**，哪怕它已经躺在 json 里。作者自己提取的 53 条 Modbus 引文一样要过
G5 反查门，当前基线 53/53（严格 36/签名 17/跳过 7）（`协议提取SOP.md:76`；门禁注册表
原文 `gate_protocol.ps1:15`）。失败处置写得毫无人情味："miss → 回③修引文，或降级
judgment；**不许改反查器放行**"（`协议提取SOP.md:77`）。

这条门对作者咬不咬人？负向测试作证：N1 用例向 modbus.json 副本注入编造引文，G5 必须
变红、52/53 拒收（`协议提取SOP.md:163-164`）——第3章的负向体系在这里客串了一次
"契约检出力"的陪练。

**岗位二：契约裁判自己也受契约管。** validate_comm_log.py 上岗前先验法条：契约文件
schema 不是 comm_log/1，拒载（`validate_comm_log.py:43-44`）；自检内嵌 3 条样例
（1 合法 2 非法），"退出码 0 = 校验器行为与契约一致"（`comm_log_contract.json:112`）
——**校验器本身也是被测对象**，与第3章 META 用例"检查自己的检查"同一纪律。

灰色地带也有显式出口：判断多于引文的部分必须降级为 judgment + needs:manual_check，
"judgment 不是耻辱，隐藏 judgment 才是"（`协议提取SOP.md:12-13`）；judgment 项在反查门
被跳过但计数显式打出，不许静默吞（`协议提取SOP.md:75`），回归测试还对关键 judgment 钉
身份（`协议提取SOP.md:141-142`）。**契约口径下没有灰色放行，只有显式降级。**

## 4.6 动手：现跑契约裁判（读者可复现）

```text
cd <mcopilot 仓库根>
python scripts/validate_comm_log.py --selftest            # 3 条内嵌样例自检
python scripts/validate_comm_log.py <你的日志>.jsonl       # 逐行校验，退出码=违规数
```

用法与退出码语义见校验器头部（`validate_comm_log.py:14-16`；`scripts/validate_comm_log.py:10-11`——建议级提示
如广播帧缺 frame_hex 不计违规）。`--selftest` 期望三行样例全部 `[OK]`（期望违规
0/2/8，`validate_comm_log.py:216`）加一行 PASS，退出码 0。

本书写作当日实跑记录（作者亲历）：样例 1 期望 0/实得 0，样例 2 期望 2/实得 2，样例 3
期望 8/实得 8，PASS，退出码 0。

想看它咬人，随手改坏一行：seq 改小（触发 I1）、给 broadcast 添个 exception_code
（触发 I2/I3）、时间改成 02-30（触发 I6）——FAIL 时退出码精确等于违规条数
（`validate_comm_log.py:251-253`）。

## 4.7 习题

**知识题**

1. 字段层已规定 exception_code"仅 direction=resp 可携带"（`comm_log_contract.json:59`），
   I3（`knowledge/contracts/comm_log_contract.json:95`）又裁一遍——重复吗？
   *参考*：不重复。字段规则管"写法合法"（取值域+携带方向），不变式管"物理可能"
   （异常只会从从站回来）；校验器两处报错文案分别定位取值越域
   （`validate_comm_log.py:126-129`）与方向归属（`scripts/validate_comm_log.py:130-131`），是两类不同的生成错误。
2. R3 为什么禁止校验器"顺手修数据"？修了不是更省事？
   *参考*：修数据=销毁采集端缺陷的现场（`knowledge/contracts/comm_log_contract.json:5`"采集端缺陷不静默修复"）。裁判一旦
   改数据，"通过"就不再证明"数据合规"，只证明"裁判认为它合规"——第三方口径
   从根上失效。
3. non_goals 把采集体量红线挂起（`knowledge/contracts/comm_log_contract.json:103`），给"契约先行"补了哪半句话？
   *参考*：契约先行≠提前编造一切标准。判不了的先挂起并写明触发条件（首批现场日志
   落库后按同款流程补），与第2章三态真值同源：挂起是设计，不是欠账。

**反事实题**（参考答案=推演裁决；第 4 题场景为构造）

4. 抽掉 R2，第一周和第一年各会发生什么？
   *参考*：第一周无事——归因照跑、指标照出，红线的缺席不可见；第一年契约门退化为
   "建议"，带病日志的指标污染所有下游结论，且没人能说清哪批指标踩在哪份日志上。
   红线的成本在设立那天，收益在你想不起它的那天。
5. 给自己的领域立一份 comm_log 式契约，先写 schema、不变式还是红线？
   *参考思路*：作者的次序是先立红线再写不变式：R1-R3 定义裁判的权力边界（拒收什么、
   拒跑到哪、改不改数据），不变式才有安身之处。没立"宁可拒收"（`knowledge/contracts/comm_log_contract.json:5`）的契约，
   不变式写得再多也只是文档。
