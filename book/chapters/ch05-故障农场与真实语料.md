## 5.1 概念：合成负样本教出"只认识造出来的错"

第2章立了三态真值；本章是 Tier A 与 Tier B 的落地现场。先回答一个容易答反的
问题：测试集里的负样本（应该检出的故障样本）从哪来？

最常见的答案是自己造——写个生成器，按理解造一百种故障。这条路有个致死后果：

> **合成负样本教出的检测器，只认识"造出来的错"。** 生成器的想象力就是检测器
> 的天花板，而现场故障的分布从不征求生成器的意见。

mcopilot 的答案是把两类样本分工（`scripts/fault_farm.py:48-50` 农场自己的
诚实边界原文）：

> 本农场的真值全部是注入参数的构造性推论——它证明「批产→检出→判卷」管线的
> 机制正确（构造类 100% 检出、clean 零误报），**不证明现场故障分布**；
> 分布校准属 Phase 2（真实语料）与 Phase 3（真机波次）。

由此推出本章三条纪律：

1. **正样本要构造（可控）**——注入参数即真值，真值在注入那一刻即知；
2. **负样本要真（分布）**——真实抓包，标签只有"是否攻击窗口"，判卷只做窗口
   口径，不装能评协议归因（`scripts/lemay_corpus.py:34-35`）；
3. **两级之间不许互相冒充**——农场的满分不兑换现场结论，现场的零误报也
   不反哺农场覆盖（第2章纪律 2 的实例化）。

## 5.2 Tier A 农场：十场景与三断言

`scripts/fault_farm.py`（1249 行，零第三方依赖）对每个场景执行同一套动作：
「注入 → 客户端/探针收发与错误事件落成 comm_log/1 条目 → 按注入参数构造标签」
——**真值在注入那一刻即知，不依赖事后观测**（`scripts/fault_farm.py:9-10`）。

十场景清单（TCP 路 8 + RTU 路 2，`scripts/fault_farm.py:22-34`），右两列是
§5.3 当日实跑的对照结果：

| 场景 | 注入 | 预期 | 实跑注入→检出 |
|---|---|---|---|
| clean | 无（正常读写 4 事务） | 检出必须为 0 | `[]→[]` ✅ |
| sticky_stale | 每响应附发旧 TID 陈旧帧 | ≥2 检出 stale_frame_tid | `[stale_frame_tid]→[stale_frame_tid]` ✅ |
| fragment_byte1 | 响应逐字节滴流 | 时序容忍，检出 0 | `[]→[]` ✅ |
| short_read | 沙盒副本注入劣化（只读 length-3） | 检出 short_read | `[short_read]→[short_read]` ✅ |
| timeout | 静默桩：连接后从站停答 | 检出 timeout | `[timeout]→[timeout]` ✅ |
| conn_reset | RST 桩：SO_LINGER(1,0) 中途断连 | 检出 conn_reset | `[conn_reset]→[conn_reset]` ✅ |
| malformed_reply | 乱码桩：协议标识≠0 | 检出 malformed_frame | `[malformed_frame]→[malformed_frame]` ✅ |
| exception_sweep | 逐请求回异常码 01.. | 检出 exception_storm | `[exception_storm]→[exception_storm]` ✅ |
| crc_corrupt（RTU） | --corrupt-next 首响应坏 CRC | 检出 crc_error | `[crc_error]→[crc_error]` ✅ |
| rtu_timeout（RTU） | no-respond 桩 | 检出 timeout | `[timeout]→[timeout]` ✅ |

每个场景自动执行**构造性真值三断言**，任一不满足即该场景 FAIL
（`scripts/fault_farm.py:36-42`）：①注入生效（从站标记或探针观测在案）；
②构造==现实（真值行指向的日志条目必须携带该 cause 的结构化签名）；③日志合法
（过 validate_comm_log 全量校验——**绝不带病出农场**）。

## 5.4 Tier B 真实语料：Lemay 测试床与"两列 CSV"的坑

`scripts/lemay_corpus.py`（566 行，零依赖：纯 stdlib struct 解析 classic pcap，
无 tshark）。数据集是 Lemay et al. CSET'16 的真机测试床抓包
（`out/_corpus_pcaps/`，不入库；缺失整门 SKIP——`scripts/lemay_corpus.py:6`）。

数据集有个阴险的结构（`scripts/lemay_corpus.py:7-12`）：每个 pcap 配一份
"预转录带标签 CSV"，但该 CSV **只有两列**（packet_index;label，0|1）——它是
逐包攻击窗口标注，不含时间/源目/功能码。想省事直接吃 CSV，得到的只是一个
"哪几包是攻击"的清单；协议字段必须从 pcap 本身解。预转录转录品的诱惑与
处理，是本管线第一课：**标签与字段分开取，各取各的一手**。

管线刻意单遍线性（`scripts/lemay_corpus.py:14-26`）：注释里自曝家史——
"上一路废稿死于过度架构，本版刻意保持简单"（V2 否决的降域重启，第9章 V2 的
正面兑现）。判卷口径同样克制：自然段误报率=标签 0 帧上的检出占比（**只报告
不设阈值**，首测无基线）；攻击段只做窗口覆盖率；主机层攻击（CnC/exploit/
moving）如实报"Modbus 面零攻击帧、协议层工具天然不可见"，不硬凑规则。

## 5.6 判读：0.4977 与 0 的差距就是答案

把 §5.5 的表读出三层结论，每层都不可省略：

- **自然段 FPR=0/12852**：检出引擎在真实正常流量上一次都没喊狼来了——
  "宁可少报也不误报"的设计（第6章）兑现为数字；
- **特征化攻击覆盖率 0.4977**：唯一在 Modbus 面可见的攻击（characterization，
  异常码风暴）只被覆盖到一半弱——真实攻击不是教科书，37 次检出对 6689 帧
  窗口，这就是"农场满分"与"现场成绩"的差距的**计量**；
- **四段 n/a**：主机层攻击根本不在协议面，协议工具天然不可见——如实报 n/a
  不硬凑规则，量程边界也是测量结果。

大纲反事实题的参考答案就在这三个数字的关系里：**只有 Tier A 农场的检测器，
遇到真实日志会怎么死？** 它不会死在报错，会死在两处不自知——把农场的 1.0000
当成现场的 1.0000（实际差距 0.4977−1.0），把"没见过"当成"不存在"（四段 n/a
若硬凑规则，FPR=0 立刻不保）。死法是静默的高估，验尸要靠本章的两级分账。
