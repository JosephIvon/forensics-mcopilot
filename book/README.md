书讲方法，代码是**案例仓**。三个工程仓各自可跑：

| 仓 | 是什么 | 位置 |

| **forensics-mcopilot**（原 `mcopilot`） | 协议域的**真值钉扎与门禁** | **本仓**（`../`）——**本书的代码锚点就是它**：`forensics-mcopilot@285da78` |
| axiscope | 数据契约与知识库（C1–C7 契约、KB0–KB8 知识库） | 同级目录（锚点 `axiscope@7b0fd88`） |

三仓之间**互不合并**——每个仓的锚点都按**自己的仓根**记相对路径，合成一个仓会破掉它。
把三仓的接缝图、发布状态与推送清单放在索引仓 `forensics-learning-index`。

**本仓这本书只讲第一个仓**，因为只有它的坐标能在这里当场复核；

> **锚点为什么落在本仓（2026-10-24 改）**：原先锚在发布前的工作副本 `mcopilot@b53ac62`。

> 而「当场可核」正是这本书要证伪的那件事。锚点必须落在**读者 clone 下来就有的仓**。
> 旧锚点不是被抹掉，是**降级成历史**：停机点 `b53ac62` 仍是当时的真实事实，
> 坐标块里以 `forensics-mcopilot@285da78` 指向读者拿得到的那份代码。

## 三、书里的引用怎么验

这本书的每个技术主张都锚在「仓库@commit + 路径 + 行号」上。**引用会过期，过期的引用比没有引用更坏**——
读的人以为出处仍然可信。所以有一道机器门禁：

```bat
python book\tools\check_doc_refs_heads.py
```

它逐条核对四个解析根（`mcopilot` / `book` / `axiscope` / `trae_factory`）里的文档引用，分八类报：

```
【一】真断链        —— 各仓 HEAD 与工作树都没有 → 必须清偿（唯一判失败的一类）
【二】仅工作树      —— 有，但没入库 → 公开后读者拿不到
【三】跨仓引用      —— 路径在另一个仓里 → 不算断链，但要能指过去
【四】反例引用      —— 行内明说该路径不存在 → 教材式举反例
【五】相对路径      —— 相对所在目录解析命中
【六】记录性引用    —— 校验报告里的历史 path 字段
【七】不入库区      —— .gitignore 声明的生成物位置（如 out/）
【八】缺仓不可判定  —— 同级独立仓不在位，本机无从核 → 不判断链，但必须喊出来
```

**当前状态：真断链 0** ✓

> **为什么要有第八类**：`axiscope` / `trae_factory` 是**独立仓，不随本仓发布**。
> 干净检出（CI、外部贡献者）上只有 `mcopilot` + `book` 在位——
> 这时"所有仓都找不到"的路径很可能就在缺的那个仓里，判成断链是冤枉，
> 而且会让 CI 第一次跑就是红的。所以缺仓期间一律归【八】，**不判失败**。
> 全仓在位时口径不变（严判，真断链必须是 0）。

门禁的仓根是**从本文件位置反推**的（`book/tools/` → `book/` → 仓根 → 仓外同级目录），
所以目录改名或搬家不用改脚本；CI 上可以用环境变量覆盖：
`MCOPILOT_REPO` / `BOOK_REPO` / `AXISCOPE_REPO` / `TRAE_REPO`。

坐标本身也有一支审计器（**按锚点 commit 读源文件**，不是读工作树）：

```bat
python book\tools\audit_vol2_coords.py      REM 逐条解析回源文件并打印被引行
```

**当前状态：引用 272，可解析 272，失败 0** ✓

> **一条纪律**：书里写的代码仓路径必须以**代码仓根**为基准
> （例如 `src/mcopilot/agents/forensics_comm.py`、`knowledge/protocols/anchors.json`），
> 不是以 `book/` 为基准。门禁按这个口径校验，改的时候别搞反。
